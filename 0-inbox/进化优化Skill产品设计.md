# 进化优化 Skill 产品设计

**日期**：2026-03-27
**状态**：初始想法，待展开

## 核心洞察

不做 SaaS（预配环境），做 **Skill**（提供内核 + AI 搭环境）。

原因：每个算法优化问题的评测环境都不同——Docker、ARM、GPU、特定编译器、特定数据集。不可能提前配好所有环境。但 AI 可以通过对话帮用户现场搭建。

## 产品形态

```
我们提供：进化内核（Skill）
  - 岛屿模型 + MAP-Elites
  - LLM 集成（bandit 选择、streaming）
  - EVOLVE-BLOCK 标记系统
  - checkpoint / resume
  - 可视化面板

用户提供：问题描述 + 初始代码

AI 帮搭：评测器、环境配置、数据管道
  ↑ 这是 Skill 模式的关键——用户跟 AI 对话就能搭好周边
```

## 为什么是 Skill 而不是 SaaS

| | SaaS | Skill |
|--|------|------|
| 环境 | 我们预配（不可能覆盖所有） | AI 帮用户现场搭（无限灵活） |
| 部署 | 在我们的云上 | 在用户的机器/云上 |
| 成本 | 我们承担算力 | 用户自己的算力和 API key |
| 适配性 | 只能做标准化场景 | 任何有评分函数的问题 |
| 门槛 | 低（上传就跑） | 中（需要跟 AI 对话配环境） |

## 类比

就像 Claude Code 的 Skill 生态——不是 Claude 预装所有能力，而是通过 Skill 扩展。进化优化 Skill 让 AI 获得"用进化优化代码"的能力。

## 实证基础

华为 MTV 比赛就是这个模式的手动版：
- 内核 = ShinkaEvolve
- 周边搭建 = Claude Code 帮我写 evaluate.py、配 streaming proxy、搞 hdspace 隧道、部署 systemd 看门狗
- 整个过程就是"人和 AI 对话搭建进化评测环境"

把这个过程产品化 = **进化优化 Skill**
