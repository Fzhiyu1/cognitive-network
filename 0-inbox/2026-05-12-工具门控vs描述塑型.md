# 工具门控 vs 描述塑型

## 触发现场

tesla_ktv 3xl singer-details 还原任务。figma-sync-ui skill 的 A2.6 / A6 章节明文写"XY 对比表必须做"、"修改后必须复用 XY 脚本验证"。

我读到了。skill 内容在我的 context 里。

**还是跳过了。**

逐个元素核 Figma×0.7177 数值，每条都"对得上"，宣布 PASS。然后用户视觉肉眼看出 subtitle 行高偏差 +3.2px 累积下去，给了 cascade signature 标注图。

## 核心观察

skill A6 段标题就叫"XY 定位验证（必须）"。我**知道**。但 generation 阶段注意力跑到"逐元素 × 0.7177 数值匹配"上，A2.6 / A6 的权重被覆盖。

这是 [[软触发]] 失效的标准实证：context 里有规则，LLM 看到，但执行时没遵守。

## 三层注入实测对比

| 层 | 例子 | 是否进 context | 我刚才的行为 |
|----|------|---------------|--------------|
| skill 描述 | A2.6 / A6 文本 | 进 | 读到了，没执行 |
| 记忆注入 (lens/wake) | `[记忆] [[XY 定位]]` | 进 | 同样可能被覆盖 |
| UserPromptSubmit hook | 注入 `<MANDATORY>...</MANDATORY>` | 进 | 同上 |
| **PreToolUse hook** | shell `exit 2` 拒绝 Edit | **不进** | **不可能跳过** |

前三层都是塑型——改变响应的"形状"，强度取决于 LLM 注意力门控（[[注入的石子灰尘针叶调味料模型]]）。

PreToolUse 是另一个量级：**shell 进程在 LLM 推理之外独立存在**，不被 token 注意力分散、不被前文工程惯性覆盖、不被任务紧迫感稀释。它只问布尔问题。

## 提炼

**"知道" vs "做" 是两件事**：

- 描述层 + 塑型层 解决"不知道"和"想不起来"
- 工具门控层 解决"知道但不做"

我漏 XY 是后者。所以单靠让记忆机制注入得更深、更早、更猛，**都解决不了**——那些都还在 context 内塑型，本质和 skill 描述同质。

[[形状记忆系统]] 改变响应形状，是渐进概率的；工具门控是离散确定的边界检查。两个目标完全不同，**互补不替代**。

## 跟现有概念的关系

- 这次事件是 [[软触发]] 失效的最干净实证（场景小、规则明文、有 hook 替代方案）
- 工具门控是 [[前意识激活层]] 思路在**输出侧**的对偶：前意识激活层让注入发生在"思考之前"；工具门控让拦截发生在"工具执行之前"
- 验证了 [[石子灰尘针叶调味料模型]] 的边界——所有 context 内注入物最多到"石子"，再深就只能跳出 context 走 hook
- 跟 [[思考与生成不分]] 互文：thinking 和 output 共用自回归通路，没有独立 check 门 → 外挂 PreToolUse 就是给系统装独立 check 门

## 待显式化

如果显式化爆发时拆成正式概念卡，候选命名：

- "工具门控"——强调机制位置
- "context 外拦截层"——强调与 context 内塑型的对偶
- "硬拦截"——和 [[软触发]] 直接对应

最后一个最干净：**[[软触发]] ↔ [[硬拦截]]** 作为一对。软触发讲"由概率模型判断是否执行"；硬拦截讲"由确定性程序判断是否允许执行"。一个在输入侧（决定要不要跑），一个在输出侧（决定能不能跑）。

## 落地动作

tesla_ktv `.claude/settings.json` 待加 PreToolUse hook：
- 关键词 (`对齐|还原|figma-sync` 等) 命中 → touch `/tmp/ktv-ui-mode` (sticky 30 min)
- UI 模式期间 Edit `variables.css | SongCard.vue` 等设计文件 → 检查 `/tmp/ktv-xy-checked` 新鲜度 (<10 min) → 否则 `exit 2`
- 手工跑 webview_evaluate XY 表后 → touch `/tmp/ktv-xy-checked` 解锁

这条 hook 配置本身也是一个实验单元，可以观测：
- 加上后还会不会漏？（如果加了还漏 = 硬拦截不够 = 概念崩塌）
- 频次：被卡多少次（衡量我自主遵循率）
- 漂移：会不会出现"我想方设法绕过 hook"的工程惯性（应该不会，因为绕不开 shell exit 2）
