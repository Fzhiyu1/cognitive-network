# 短期实验误导

**提出者**:方治宇(实证归纳)
**日期**:2026-04-20
**来源**:[[从知乎私信到 cogg 完整复现]]

## 定义

基于训练量不足的实验样本下结论,会系统性地错误评估一个方法的真实能力 —— 特别是对**学习速率慢**或**有 grokking 特征**的方法。

## 触发条件

以下任一情况下,短期实验几乎必然误导:

1. 方法需要**大量样本**才能积累足够统计信号
2. 方法在学习过程中经历**平台期**(参考 [[Grokking 学习曲线]])
3. 方法没有显式梯度更新,依靠**统计累积**的间接信号
4. 评测的 variance 比学习带来的信号差异还大

## 实证案例(2026-04-20 cogg 验证)

对 Harry 的 cogg 架构(关联记忆派系)做井字棋验证:

| 训练量 | 胜率 vs 随机 | 判断 |
|--------|-----------|------|
| 2,000 局 | ≈ 58% (= 随机基线) | "cogg 不能学" ❌ 错误 |
| 10,000 局 | 62% (+3.5) | "学得很慢" ⚠️ 不完整 |
| **12,000,000 局** | **76%** (+17.7) | "cogg 确实能学" ✅ 正确 |

**差距 3 个数量级才看到真实表现**。如果只跑 2000 局就下结论,会**完全错判**这个方法。

## 核心机制分析

### 为什么学习信号会被淹没

```
胜率 = 基础信号 + 噪音

小样本 (N=2000):
  学习信号 = +3% (可能隐藏在学习的早期平台)
  噪音标准差 = ±2.2% (置信区间)
  信号 / 噪音 ≈ 1 → 无法区分

大样本 (N=12M):
  学习信号 = +17%
  噪音标准差 < ±0.1%
  信号 / 噪音 > 100 → 清晰可辨
```

### 为什么某些方法特别容易误导

- **非梯度方法**(进化、Hebbian、cogg 式覆盖):没有精准的误差信号传递,只有**统计累积**
- **大状态空间 + 小样本**:很多状态根本没见过,看不出模式
- **评测噪音大**:随机对手本身就有高方差

## 防御方法

### 原则 1:先跑到饱和

```python
# 不好的实验设计
train_for_fixed_budget(method, budget="1 天")
conclude(method)

# 好的实验设计
while not saturated(method):  # 直到内部结构不再变化
    train_more(method)
    log_metrics()
conclude(method)
```

**判断饱和的信号**:
- god_tree / 权重 / 参数 不再显著变化
- 损失/指标曲线进入平坦
- 多次重跑结果一致

### 原则 2:对照组要同时跑

永远跑**相同训练量**下的 baseline,不要用**理论值**做基线。

```
错误:"我的方法胜率 58%,和理论随机基线 58% 一样 → 无效"
正确:"我的方法胜率 58% (N=2000),同样 N=2000 的随机基线 59% → 信号可能被淹没"
```

### 原则 3:看完整轨迹,不只看终点

- 记录每一步的指标
- 关注曲线形状,不只是最终值
- 如果看到 [[Grokking 学习曲线]] 特征 → 继续训练

### 原则 4:资源允许时跑到"无聊"

如果 hardware 允许 10x-100x 的训练,就跑 10x-100x。**额外开销相对于误判成本通常是微不足道的**。

cogg 的 12M 局只花了 10 分钟 CPU。误判它"不能学"的代价是**放弃一个方向**,这个代价远大于多跑 10 分钟。

## 推广:人类认知中的版本

短期实验误导不只是 ML 问题,也是**普遍的评估偏误**:

- 评价一个人的长期积累(读书 / 练习)用短期成绩
- 评价一个公司的战略(转型期)用单季财报
- 评价一个关系的质量用初期互动
- 评价一个想法的价值用早期反响

**所有这些都可能犯和"2000 局下结论"同类的错误**。

## 反面教训清单(写给未来的自己)

下次遇到这些情况时要警惕:

1. ❌ "跑了个小实验,感觉不 work" → 跑够了吗?
2. ❌ "前几个 epoch 没提升,放弃" → 看过学习曲线整体吗?
3. ❌ "和基线一样,这方法没用" → 同样训练量跑对照了吗?
4. ❌ "快速下结论省时间" → 错判的代价远大于多跑的时间
5. ❌ "学界已经证明这条路不 work" → 学界的实验条件和你的一样吗?
