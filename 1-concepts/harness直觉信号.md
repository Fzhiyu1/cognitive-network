# harness直觉信号

**提出者**：fangzhiyu
**日期**：2026年8月18日
**来源**：[[时序表征调研：从NeurIPS最佳论文到harness直觉]]

## 定义

用现成 embedding 模型（MiniLM，384 维）编码 agent 会话事件内容，滑窗均值作状态，线性探针预测"该会话最终能否正常收尾"。它给 harness 补上此前不存在的一层感官：从只知道"我在做什么"，到知道"我做得怎么样"——一个快、便宜、说不出理由、大体准的直觉层。

## 实证

956 个真实 Claude Code 会话、73880 个事件（本机 `.claude/projects`），留出验证：

| 指标 | 结果 |
|---|---|
| 只看会话前 25% 预测成败 | **AUC 0.832** |
| 前 50% / 75% | 0.740 / 0.787 |
| 工具错误率基线 | 0.485 ≈ 瞎猜 |
| 进度预测（语义+log(t)） | 0.608（词袋仅 0.319） |
| 语义之上再做时序对比学习 | 0.400，**负增益** |

三个反直觉发现：

1. **会话的命运在前 1/4 已写下大半** —— 过程奖励存在性的直接证据
2. **报错多少与成败无关** —— 失败会话不是错误多的会话，而是另一种语义形态（目标涣散、兜圈、用户反复纠正）；一切基于错误计数的启发式因此失灵
3. **赢的是"内容进状态"这个朴素动作，不是先进表征** —— InfoNCE 优化目标与成败信号不重合，反而压掉有用维度

## 下游应用（均只读，暂不给方向盘）

- 止损：28% 烂尾会话的后半段 token 是纯损耗，25% 处可三选一（降级收尾/问用户/停）
- 并行裁剪：3 分支各跑 1/4 砍 2 留 1，约 1.75 倍成本换 best-of-3
- 数据飞轮：P(成功) 曲线自动筛选 SFT 轨迹、标记错误动作

## 局限

标签是"是否正常收尾"的近似，未做跨项目验证（可能记项目作弊），仅在单一用户分布上成立；17% 误判使其只配当仪表不配当决策者。直觉单独存在无价值——须接上第一个真实动作才兑现。
