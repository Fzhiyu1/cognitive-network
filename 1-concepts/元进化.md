# 元进化

**提出者**：fangzhiyu
**日期**：2026年3月27日
**来源**：华为 MTV 比赛进化实践后的灵感

## 定义

用 LLM 进化来优化 LLM 进化器本身。先跑几轮进化收集结果数据，然后把"进化过程 + 结果 + 原始问题"作为输入，让另一个进化器来优化进化策略（prompt 模板、补丁类型概率、采样策略、评分函数设计等）。

## 核心递归

```
第 0 层：人写算法
第 1 层：LLM 进化优化算法            ← 我们现在在这里
第 2 层：LLM 进化优化进化器           ← 这个想法
第 3 层：LLM 进化优化"优化进化器的进化器"  ← 理论上可以继续
```

## 可以进化的组件

| 组件 | 当前状态 | 进化目标 |
|------|---------|---------|
| Prompt 模板 | ShinkaEvolve 已支持 prompt evolution | 进化更好的 prompt |
| 补丁类型概率 | 固定 diff 60% / full 30% / cross 10% | 自适应调整 |
| 评分函数设计 | 人工设计 | 进化发现更好的评分方式 |
| 岛屿迁移策略 | 固定间隔 | 自适应迁移 |
| LLM 选择策略 | UCB1 bandit | 进化更好的 bandit 参数 |

## 评分函数的评分函数

元进化的关键问题：怎么评价一个进化器好不好？

答案：**同一个问题上，跑 N 代后的最优分数。** 进化器 A 跑 100 代得分 80，进化器 B 跑 100 代得分 95 → B 更好。

这个元评分函数天然存在且可自动化。

## 已有的部分实现

ShinkaEvolve 的 `evolve_prompts: true` 就是元进化的一个子集——进化 prompt 模板。但只进化了 prompt，没有进化整个框架。

## 真正的产品应用：进化 Skill 的搭建能力

**修正**：元进化的第一个落地场景不是进化算法内核，而是进化 Skill 引导 AI 搭建环境的能力。

### 验证集构建

先手动跑通几个不同问题的完整进化流程：

| 问题 | 环境搭建过程 | 预期结果 |
|------|------------|---------|
| MTV 比赛 | Docker + ARM Runner + streaming proxy + hdspace 隧道 + systemd | score ≈ 138 |
| meomory FunSearch | Python sandbox + 5 岛模型 + LLM 采样 | P@1 ≈ 26% |
| 更多问题... | 各自不同的环境 | 各自的 baseline |

这些成功案例就是**验证集**——已知问题 + 已知正确搭建过程 + 已知结果。

### Skill 的评分函数

```
给定：一个新问题的描述 + 初始代码
Skill 引导 AI：搭建评测环境 → 配置进化框架 → 启动进化
评分：
  1. 冒烟通过？（环境搭通，能编译能跑）     → 0/1
  2. 结果匹配？（跑 N 轮后分数接近预期）    → 0/1
  3. 效率？（AI 用了多少轮对话搭好的）       → 越少越好
```

### 自举循环

1. 人手动搭几个环境（积累验证集）
2. 写 Skill v0（基于手动经验）
3. 用验证集评分 Skill v0
4. **进化 Skill → Skill v1**（用评分函数驱动）
5. Skill v1 帮用户搭新环境 → 新的验证集
6. 继续进化 → Skill v2 ...

**Skill 自己进化自己的搭建能力。** 这是"评分即解题"的递归应用。
