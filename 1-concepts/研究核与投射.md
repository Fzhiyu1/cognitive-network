# 研究核与投射

**提出者**：fangzhiyu & Claude (Opus 4.7)
**日期**：2026-05-09
**来源**：从 `/init` 重盘 ~/run 工作区到 vision 显性化的会话

---

## 定义

研究路径在外部呈现为多个独立项目，但底层可能共享同一组**核（nucleus）**。

- **核** = 一个稳定的研究命题或方向（"什么是记忆"、"AI 如何有生存驱动"）
- **投射** = 同一个核在不同时间 / 不同载体 / 不同抽象层的表达（一个仓库、一篇文章、一个工具）

项目膨胀时的散乱感，往往不是因为方向太多，是因为**核没显性化**——所以每个投射看起来像独立方向。

## 核 vs 项目

|  | 项目（投射层） | 核（命题层） |
|---|---|---|
| 数量 | 仓库数（可见） | 核数（待显性化） |
| 切换成本 | 高（每仓重载上下文） | 低（同核共享心智） |
| 决策密度 | 高（每仓独立决策） | 低（核指引投射） |
| 死亡条件 | 仓库 stale | 命题被否决或穷尽 |

## 案例（fangzhiyu, 2026-05-09 显性化）

13 个仓库重新分类为：

**直接朝向 vision 的核**：
- **核 1（记忆范式）**: [[记忆假肢]] meomory → wake（wake 是对 meomory 检索范式的范式否决，不是补丁）
- **核 2（非主流认知架构）**: brainstem → cogg-for-harry → harry-cogg（[[人工脑干]] / [[目标真空假说]] / 非 Transformer / 非反向传播）

**substrate 投资（不直接朝向 vision，但让 vision 可被追求）**：
- **核 3（设计-代码自动化）**: tesla_ktv → 一整套设计验证 MCP — **经济基础**
- **核 4（Claude Code 工具生态）**: atlas / claude-bridge / claude-hud / skill-manager — **能力放大**

**vision**：成为超级个体（[[超级个体公式]]）/ 研究认知科学 / 做出那个 AGI。

13 个仓库 = 4 核 × 不同投射 + 历史尾巴（fire-safety / xuexitong / 玩具 / 空目录）。

## 关键性质

1. **核明确，边缘自动萎缩** —— 不必主动做减法。一旦核显性化，不在核谱系内的项目自然 stale，无需杀。
2. **散乱痛感来自 vision 未显性化** —— 而不是 vision 不存在。
3. **新建项目前先问"是不是同核投射"** —— 是的话，应该是已有项目的延伸而不是新仓库。
4. **核数应远小于项目数** —— 通常 3-5 个核能覆盖几十个项目。如果核数也膨胀，那 vision 本身没成形。

## 与决策疲劳的关系

决策疲劳的真正原因，可能不是"决策计算量大"，是 **"我不知道我自己最在乎什么"** 的不安伪装成决策疲劳。

证据：对每个项目都能写 5 条深挖路径（执行层不缺），但被问"半年后想被认可在哪里"时给不出答案（价值层缺）。

这意味着：**决策不是计算问题，是价值问题。** 试图用"拟合自己的决策模型"来代替决策是陷阱——一个拟合过去 8 个月行为的模型只会成为**保守强化器**，推着你重复自己。决策需要的是显性化的核，不是模型代理。

## 与 wake 范式的同构

研究核与投射 / 记忆 substrate 是同一个范式在不同对象上的应用：

| 对象 | 错误范式 | 正确范式 |
|---|---|---|
| 记忆 | 检索（meomory） | substrate 形状响应（[[多层有损压缩]] / wake） |
| 决策 | 模型代理（拟合过去） | 核显性化 → 投射自然展开 |
| 项目管理 | 减法 / 工具优化 | 核明确 → 边缘自动萎缩 |

三者共享同一个底层洞察：**不要把动态过程做成查表。**
