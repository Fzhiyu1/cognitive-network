# 研究者过拟合

**提出者**：fangzhiyu
**日期**：2026年3月19日
**来源**：meomory 项目中的自我反思——从 87% 的兴奋到 0.9% 的崩塌

## 定义

研究者对自己的实验结果产生过拟合：被早期的高分锚定，后续所有判断都围绕这个数字展开，失去了对评测方式本身的质疑能力。算法过拟合训练集，研究者过拟合自己的指标。

## 我的案例

### 时间线

```
3月16日  看到 87.4%（500题）  → "这也太强了吧"
3月17日  写博客发掘金/知乎    → "三个AI互相竞争，发明了我看不懂的算法"
         全量验证 56.6%       → "膨胀比 1.5x，还行"
         LongMemEval 92.3%    → "接近 SOTA！"
         跟 DRAGON 对比       → "我们比 ACL 2024 的方法强"
3月18日  README 更新 60.1%    → 自信地写 SOTA 对比表
3月18日  冷启动实验 0.9%      → "……全是假的"
3月19日  在线流式真实分数 26%  → 这才是真实水平
```

### 从 87% 到 26%，我的认知偏差

| 偏差 | 表现 | 后果 |
|------|------|------|
| **锚定效应** | 87% 成了心理锚点，后续所有数字都跟它比 | 56.6% 觉得"还行"，其实该警觉 |
| **确认偏差** | 只关注支持"算法很强"的证据 | LongMemEval 92.3% 让我更确信，没去测泛化 |
| **公开承诺** | 博客已发、README 已写 | 承认错误的心理成本变高了 |
| **沉没成本** | 投入了几天几夜的进化实验 | 不想接受"方法论有问题"的可能 |
| **光环效应** | "AI 自己发明了 Adam + BatchNorm" 太酷了 | 酷的故事让我不想检验它的基础 |
| **达克效应** | 对评测方法论理解不够 | 没有第一时间做 train/test split |

### 转折点

不是某篇评论或某个数字。是**实际应用的时候**。

把进化出的算法集成到搭子（dazi）的记忆系统里，做了一个 Web 测试台，灌入 LoCoMo 的 272 个对话片段，开始真的用。

发现：
- LLM 说"没找到"但 Judge 还是标正确 → 反馈链路有 bug
- 同一个问题问 6 次 DGD 分数涨到 97%，但换个问题直接崩 → 只对重复有效
- cosine 本来就能找到的，DGD 没有改善；cosine 找不到的，DGD 也找不到

benchmark 上的数字是抽象的，在搭子里亲手用的时候才感受到**这个东西不对劲**。

然后才设计了冷启动实验：

```python
train 500 题 → 10 轮 GT 反馈 → test 1476 题
gen059: Train=87% Test=0.9%
```

0.9% < cosine baseline 21.2%。学了反而更差。数字只是确认了体感。

## 为什么研究者比算法更容易过拟合

1. **算法没有情感**——87% 和 0.9% 对算法来说只是数字。对研究者来说，87% 是兴奋，0.9% 是痛苦
2. **算法不发博客**——算法不会因为公开了结果就不想承认错误
3. **算法不理解"意义"**——研究者会给数字赋予意义（"超过 SOTA"、"改变了什么"），这些意义成了需要保护的投资
4. **算法每次都从零开始**——研究者带着上一次实验的记忆和情感进入下一次

## 防御措施

### 已经建立的

- **冷启动测试**成为标准流程——任何新算法都要过 train/test split
- **在线流式评测**替代了 train=test——fitness 函数与真实场景对齐
- **知识卡片记录失败**——不只记录发现，也记录幻觉

### 需要建立的

- **发布前等 48 小时**——兴奋时不发博客，等冷静后再写
- **主动找反例**——每个好结果都主动设计能证伪它的实验
- **外部校验**——找一个不了解项目背景的人看评测方法
- **区分"好看"和"有效"**——"AI 发明了 BatchNorm"很好看，但不等于有效

## 收获

**虚的：** 87%、60.1%、92.3% 这些数字全部作废了。博客里的对比表是错的。

**真的：**
- 理解了 fitness 函数设计的重要性——比算法本身重要
- 理解了共享矩阵的根本限制——不是算法问题，是架构问题
- 理解了进化搜索的能力和边界——能突破人类偏见，但不能突破 fitness 的偏见
- 建立了诊断工具链——冷启动测试、在线评测、打乱顺序
- 亲身体验了从幻觉到清醒的过程——这比任何论文都教得深

## AI 研究者也会过拟合（2026-04-11 kaiwu 实证）

人类研究者会过拟合自己的指标。**AI 研究者（Claude）也会。** 认知路径完全相同：

```
人类（3月）：87% → "太强了" → 发博客 → 冷启动 0.9% → "全是假的"
AI（4月）：+3.4% → "首个keep" → 更新best.py → 从头训练-15% → "伪阳性"
```

AI 研究者的过拟合表现：
- **锚定 exp_5 的 +3.4%**——立刻标记 keep，更新 best.py，在此基础上叠加后续实验
- **跳过回顾步骤**——急于产出下一个实验，三次被人类提醒"你看了进化数据吗"
- **不质疑评估方法**——直到人类问"需不需要从头训练"，才意识到暖启动评估的根本缺陷

这说明**研究者过拟合不是人类特有的认知偏差，是评估系统的结构性问题**——无论评估者是人还是 AI，只要评测方式与真实目标不一致，就会过拟合短期结果。

AI 研究者甚至缺少人类的一些防御机制：
- 没有"感觉不对劲"的直觉（人类在搭子里亲手用 DGD 时感到不对劲，先于数据）
- 没有前额叶的元监控（[[没有前额叶的皮层]]）——不会自发怀疑自己的判断
- 必须依赖外部干预（人类提醒、cron 强制回顾）才能打破锚定

## 最重要的一句话

**如果进展太快太好，先怀疑评测方式。**

87% 两小时就达到了。真实的 26% 花了一整晚还在挣扎。慢和难才是真实世界的样子。
