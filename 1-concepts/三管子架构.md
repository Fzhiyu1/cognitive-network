# 三管子架构

**提出者**：fangzhiyu
**日期**：2026年3月31日
**来源**：从 MTV 代码进化 → 反馈循环统一视角 → 进化的组件拆解

## 定义

任何能"持续变好"的系统，本质上只需要三根管子：

1. **反馈环** — 尝试 → 评价 → 调整
2. **记忆** — 保留好的，积累经验
3. **自指涉** — 系统能改善自身的改善过程

进化恰好同时包含这三个，但它们是独立组件，可以分别设计、独立替换。

## 组件拆解

### 管子 1：反馈环（调整机制）

| 实现方式 | 载体 | 速度 |
|---------|------|------|
| 进化（LLM 变异） | 代码 | 分钟 |
| RL（梯度下降） | 权重 | 毫秒 |
| A/B 测试 | 产品方案 | 天 |
| 人类反馈 | 任意 | 秒-天 |
| 市场竞争 | 产品/价格 | 实时 |

不需要绑定"进化"——任何能产生调整的机制都行。

### 管子 2：记忆（积累机制）

| 实现方式 | 存储形式 | 特点 |
|---------|---------|------|
| 代码继承（parent） | 代码结构 | 隐式，不可解释 |
| archive/种群 | 多个候选 | 保持多样性 |
| 图书馆（知识提炼） | 文字描述 | 显式，可传递 |
| DGD 矩阵 | 权重分布 | 有损压缩，能泛化 |
| 向量库 | 原始记录 | 无损，不泛化 |

不需要绑定"种群" —— 任何能积累的机制都行。

### 管子 3：自指涉（元改善机制）

| 实现方式 | 改善什么 |
|---------|---------|
| evolve_prompts | 改变异的指令 |
| 元进化 | 改进化的策略 |
| AI-Scientist | 改对问题的理解 |
| 全局状态注入 | 改搜索的方向 |
| 人类复盘 | 改整个方法论 |

不需要绑定"元进化"——任何能让系统认识自身状态并调整的机制都行。

## 核心洞察

**不需要一个"进化"的系统，需要一个"活"的系统。**

"活"= 三根管子都接上了。

- 只有反馈环，没有记忆 → 随机搜索（不积累，每次从零开始）
- 有反馈环和记忆，没有自指涉 → 进化（能积累但会收敛到局部最优）
- 三根管子都有 → 持续自我改善的系统（能识别自身瓶颈并突破）

## 壳子的设计

```
不是：evolve(code, eval_fn)
而是：activate(system, feedback, memory, meta)

给任何系统接上三根管子，它就活了。
```

用户不需要理解"进化"、"RL"、"遗传算法"这些具体技术。他只需要定义：
1. 怎么判断好坏（反馈环）
2. 好的东西存哪（记忆）
3. 系统怎么知道自己卡住了（自指涉）

具体用进化还是 RL 还是别的，壳子自动选择。

## 与现有系统的对照

| 系统 | 反馈环 | 记忆 | 自指涉 | 效果 |
|------|-------|------|--------|------|
| ShinkaEvolve | ✅ LLM 变异 | ✅ archive | ⚠️ evolve_prompts（弱） | 能进化但会收敛 |
| AlphaGo | ✅ 自我对弈 | ✅ 网络权重 | ❌ | 极强但固化 |
| 人类科学 | ✅ 实验 | ✅ 论文/教科书 | ✅ 科学哲学/方法论 | 持续突破 |
| 生物进化 | ✅ 自然选择 | ✅ 基因 | ❌ | 强但极慢 |
| **理想壳子** | ✅ 自适应 | ✅ 多层级 | ✅ 元改善 | ？ |

人类科学是唯一三管齐全的系统。这也许解释了为什么它是已知最强的知识生产机制。
