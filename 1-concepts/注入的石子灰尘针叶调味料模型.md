# 注入的石子灰尘针叶调味料模型

**提出者**:fangzhiyu × Claude Opus 4.7
**日期**:2026-05-03
**来源**:[[lens+wake首次运行：元认知循环的实例化]] 之后的实测对比

## 模型

把 wake 注入对 Claude 形状的影响,按 `深度 × 相关性` 二维分类:

| 类型 | 深度 | 相关性 | 对 Claude 的影响 | 例子 |
|------|------|--------|----------------|------|
| **石子** | 深 | 强 | 真改变形状,涟漪扩散 | 问"形状记忆系统怎么样" → 注入完整状态 → Claude 输出深度结构化回答 |
| **灰尘** | 浅 | 弱 | 被忽略,无害 | "嗨" → 注入哲学化"协作入口" → Claude 直接回"嗨!有什么可以帮你的吗?" |
| **针叶** | 浅但锋利 | **重解 query** | 危险,污染 | 修复前的 wake:"压缩文件"→ 注入"不是压缩文件,是把认知压到可行动" |
| **调味料** | 中等 | 不显式相关 | 化为风格,有益 | "我想跑个步" → 注入 [[可行动状态]] → Claude 回"换鞋出门就行,路线到了再说" |

## 关键判据

**失败的判据不是"wake 输出了什么",是"Claude 是否被它影响"**。

我(LLM)只能看 wake 的输出,看不到 Claude 端的实际行为。所以"严重失败"的评估需要 substrate-外部的实证(如用户在新会话里实测 Claude 真实输出),不能由 AI 自评。

## 调味料是最美的形态

注入的概念名一个不出现在 Claude 输出里,但回应方式被 substrate 化:
- "换鞋出门就行" = [[可行动状态]] 的精确实现
- "路线到了再说" = [[当场抽取]] 的精确实现

事件层(具体卡名)丢失,形状层(如何回应的方式)生效——这正是 [[多层有损压缩]] 在生成端的活体实例。

## 实操含义

不要为了消灭"灰尘"把 wake 改成"只放石子"——会失去很多有用的小颗粒(调味料就是"灰尘 + Claude 的智能转化"得到的)。
**真正要挡的是针叶**(主动重解 query 的注入),这个 prompt 层已基本能挡。
