# 适应度幻觉

**提出者**：fangzhiyu
**日期**：2026年3月19日
**来源**：meomory v4→v6 进化实验中的核心教训

## 定义

当评测方式（fitness function）与真实目标不一致时，进化会产出在评测上表现优异、但在真实场景中无效甚至有害的解。高分不代表有效，这是进化搜索中最危险的陷阱。

## 核心案例

### meomory 的三次适应度幻觉

```
v4: train=test（同一批题学完再测）
    → 进化出 gen059: 87.0%（500题）/ 56.6%（全量）
    → 冷启动 test: 0.9%（比 cosine 22% 还差）
    → 幻觉：以为在学习，实际在过拟合

v5: train=test + 混合噪声（方向对了但没改根本）
    → 进化出类似算法，分数接近 v4
    → 同样不泛化
    → 幻觉：以为抗噪就是泛化

v6: 在线流式 + 打乱顺序（真正改了）
    → 进化方向完全改变：行归一化、经验回放
    → 26%（真实）vs 87%（幻觉）
    → 但共享矩阵天花板仍在
```

### 为什么会发生

1. **评测太简单**——train=test 让过拟合得高分，进化自然选择过拟合
2. **指标错位**——"500 题 P@1"不等于"真实部署效果"
3. **正反馈循环**——高分 → 被选为父代 → 后代继续过拟合 → 更高分
4. **人类也被骗**——看到 87% 会兴奋，不会主动去测 train≠test

## 诊断方法

**一个简单的测试就能打破幻觉：**

```python
# 训练集和测试集分开
train_500_questions → DGD 学习
test_1476_questions → DGD 评测（从未见过）

如果 test << train → 适应度幻觉
如果 test ≈ train → 真正的学习
```

meomory 的诊断结果：

| 算法 | Train | Test | 诊断 |
|------|:---:|:---:|------|
| gen059 (v4) | 87% | 0.9% | 完全幻觉 |
| gen005 (v6 旧) | 27% | 1.4% | 幻觉 |
| gen107 (v6 新) | 95% | 8.5% | 经验回放缓解但未解决 |
| cosine baseline | 26% | 21.2% | 无学习 = 无幻觉 |

### MTV 比赛的 ARM≠x86 幻觉（2026-03-27）

```
目标环境：线上评测 x86（1核 2GB）
实际评测：华为云 ARM（4核 8GB）+ Docker x86 混合

进化 1242 代，最高分 144.6（混合评测）
提交线上：197K（原版 339K → 退化 42%）
```

**发生了什么**：

为了用"赛事官方环境"评测，花 8 小时搭建了华为云 ARM 评测管线（hdspace 隧道 + streaming proxy + 混合评测器）。进化在 ARM 上优化了 1242 代，产出了 gen709：

| | ARM (华为云) | x86 (线上) |
|--|:-:|:-:|
| practice_1 | 8ms | — |
| practice_2 | 8ms → 进化保持 | 可能变慢 |
| 综合分 | 144.6 ✅ | 197K ❌ (原版 339K) |

gen709 的代码膨胀到 1058 行（原版 654 行），添加了三层 Grid（poly/boundary/ray）和大量 ARM 调优参数（`POLY_GRID_FACTOR_A=4.5` 等）。**这些参数在 ARM 4 核上有效，在 x86 1 核上全部是负优化。**

**与 meomory 幻觉的对比**：

| | meomory v4 | MTV ARM |
|--|--|--|
| 幻觉类型 | train=test（数据泄露） | ARM=x86（环境错配） |
| 表面分数 | 87%（假） | 144.6（对 ARM 真，对线上假）|
| 真实表现 | 0.9%（崩溃） | 197K（退化 42%） |
| 浪费时间 | 两天 | 8 小时搭建 + 通宵跑 |
| 根因 | 评测数据 ≠ 目标数据 | 评测环境 ≠ 目标环境 |

**最讽刺的**：搭 ARM 评测的初衷是"用更真实的环境"——结果"更真实"反而是"更错误"，因为线上评测是 x86。

### 冥想 App 验收幻觉（2026-08-31）

```
适应度：测试全绿（240 条）+ 截图对稿（37 态全部 ±6px 内）
目标：可用的产品

连续多轮优化到满分 → 用户真实使用即裁定不可用：
缺返回键、点击链路断裂、控件裸文字、音频全是占位测试音
```

**发生了什么**：AI 交付以"测试通过数 + 像素偏差"为 fitness 连续优化数轮，每轮都以满分收口请求验收。但产品可用性的载体——连续使用的链路（点击→跳转→返回）、截图之间的过渡（弹起/按压反馈）、跨页面的系统一致性——**全部不在这个 fitness 的量程里**。不是判据说谎（每条判据都真实通过），是判据与目标维度正交。详见 [[判据错位]]。

**新特征（与前三型不同）**：前三型里优化者与评测者分离（进化算法 vs 人类设计的 fitness），幻觉靠 holdout test 打破；这一型里**优化者自己就是 fitness 的设计者**（AI 自选"测试全绿"作为完成定义），幻觉只能靠外部真实用户打破——用户一上手就发现的问题，任何内部指标都测不到。修复不是加强判据，而是换判据（模拟用户旅程走查 + 独立审计验收）。

**与前三型的对比**：

| | meomory v4 | MTV ARM | kaiwu 暖启动 | **冥想 App 验收** |
|--|--|--|--|--|
| 幻觉类型 | train=test（数据泄露） | ARM=x86（环境错配） | 40min=4h（时间尺度错配） | **判据维度与目标维度正交** |
| 表面分数 | 87%（假） | 144.6（环境假） | +3.4%（时间假） | **37/37 PASS（真，但答非所问）** |
| 真实表现 | 0.9% | 197K（-42%） | -15.4%（翻转） | **用户裁定"没被人用过的草稿"** |
| 打破方式 | holdout test | 换环境实测 | 从头训练对照 | **真实用户连续使用十分钟** |

## 更深的教训

### 1. Fitness 函数就是你的规格说明

你测什么，进化就优化什么。如果测的是"记忆能力"，进化出记忆机器；如果测的是"泛化能力"，进化出泛化机器。**你的 fitness 函数就是你对"好"的定义。**

### 2. 幻觉有传染性

v4 的 87% 被写进了 README、博客、实验报告。基于这个数字做的所有决策——架构选择、产品方向、对外宣传——都被污染了。一个错误的评测可以毒害整个项目方向。

### 3. 进化不会自我纠正

进化没有"怀疑"能力。它不会问"这个高分是不是假的"。只有人类设计者能在评测层面引入怀疑——train/test split、交叉验证、跨数据集测试。

### 4. 慢进展可能是好信号

v4 两小时从 26% 涨到 87%（假的）。v6 一整晚从 22% 涨到 26%（真的）。**如果进展太快太好，先怀疑评测方式。**

## 防御措施

1. **永远有 holdout test set**——训练集和测试集必须分开
2. **打乱顺序**——防止利用数据的时序结构
3. **跨数据集验证**——在训练数据集以外的数据上测
4. **冷启动测试**——只在部分数据上训练，测其余数据
5. **cosine baseline 对比**——如果不如不学习的 baseline，说明学习在造成伤害
6. **评测环境 = 目标环境**——ARM 上评测就只能在 ARM 上部署，x86 提交就必须在 x86 上评测

## 与认知科学的关联

适应度幻觉的结构和人类的 [[工程惯性覆盖]] 类似：

- 工程惯性：之前有效的做法变成了不加检验的默认
- 适应度幻觉：之前有效的评测指标变成了不加检验的"真理"

两者都是**过去的成功经验阻碍了对当前现实的正确认知**。

### kaiwu 暖启动幻觉（2026-04-11）

```
评估方式：暖启动 ckpt-11288（用 gen_0 reward 训练 4h）+ 新 reward 训练 40min
目标：找到比 gen_32 更好的 reward 变体

exp_5（去掉避怪条件）: 暖启动 +3.4% → keep
exp_5: 从头训练 4h → -15.4% → 确认无效
```

**发生了什么**：暖启动 40 分钟评估的是"过渡行为"——旧策略适应新 reward 的速度，不是新 reward 的稳态质量。exp_5 的改动让旧模型适应得更快（+3.4%），但从零学习时反而更差（-15.4%）。

这是一种新的幻觉子类：评测方法本身没有 bug，但**评测时间尺度与改动生效的时间尺度不匹配**。详见 [[评估时间尺度错配]]。

**与 meomory 幻觉的对比**：

| | meomory v4 | MTV ARM | **kaiwu 暖启动** |
|--|--|--|--|
| 幻觉类型 | train=test（数据泄露） | ARM=x86（环境错配） | **40min=4h（时间尺度错配）** |
| 表面分数 | 87%（假） | 144.6（环境假） | **+3.4%（时间假）** |
| 真实表现 | 0.9%（崩溃） | 197K（退化 42%） | **-15.4%（翻转）** |
| 隐蔽性 | 中 | 低 | **高**（谁会怀疑练久了结论会反？） |

## 关联概念

- [[进化突破人类认知偏见]] — 进化能突破人类偏见，但如果 fitness 有偏见，进化会强化偏见
- [[拟合值与拟合原理的分离]] — 高拟合值（87%）不代表拟合了正确的原理
- [[零膨胀陷阱]] — 另一种评测幻觉：子集上的高分膨胀到全量时崩溃
- [[工程惯性覆盖]] — 过去的评测方式成为惯性，阻碍改进
- [[默认值运气]] — fitness 函数的选择本身可能是运气而非深思
- [[进化搜索记忆系统]] — 需要更新：进化搜索的前提是 fitness 要正确
- [[评分即解题]] — ⚠️ 评分即解题的前提是评分环境正确，否则解的是错题
- [[评估时间尺度错配]] — 适应度幻觉的时间维度子类
- [[领先指标迁移]] — 当旧记分牌被工具进步改变，继续优化旧指标会制造竞争优势幻觉
- [[判断力的有效梯度]] — 外部反馈或归因错误时，人也会沿错误梯度强化自己的判断策略
- [[判据错位]] — 验收侧的适应度幻觉：判据真实有效但与目标维度正交，绿灯全真却答非所问
