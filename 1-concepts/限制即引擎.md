# 限制即引擎

**提出者**：fangzhiyu
**日期**：2026年3月31日
**来源**：Ember 改造讨论 → ALife 项目调研 → 为何传统 ALife 从未进化出"眼睛"→ 原语设计的核心矛盾

## 定义

在进化系统中，**限制是复杂性涌现的引擎**。给生物的能力越少、信息越受限，进化被迫发明的结构越复杂。反之，给得越多，涌现越少。

## 核心机制

```
上帝模式：一行代码读取全局状态 → 不需要感官 → 不会进化出眼睛
生存模式：只能感知相邻 1 格 → 被迫发明远距感知 → 进化出眼睛
```

每一种限制，对应一种被迫涌现的结构：

| 限制 | 涌现的结构 | 生物学对应 |
|------|-----------|-----------|
| 只能感知相邻格 | 多感知细胞排列 = 远距感知 | 眼睛 |
| 感知消耗能量 | 选择性感知 | 注意力 |
| 不能直接移动 | 连接+交替收缩 | 腿/肌肉 |
| 不能远距取食 | 伸出+抓回 | 手/触手 |
| 不能直接复制自己 | 逐步写入邻居 | 有成本的繁殖 |
| 通信只能写相邻格 | 链式信号传递 | 神经系统 |

## 反面验证

传统 ALife（Bibites、biosim4 等）几十年没进化出"眼睛"级复杂结构，原因之一是给了太高级的 API：

- `sense(direction)` → 感知已经是原语，不需要进化
- `move(direction)` → 运动已经是原语，不需要进化
- `reproduce()` → 繁殖已经是原语，不需要进化

**高级 API = 预设答案 = 取消了进化的题目。**

## 设计原则

进化系统的原语设计，不是"给生物什么能力"，而是"**不给**什么能力，逼它自己造"。

最低限度的物理规则（足够支撑涌现的最小集合）：

```
1. 空间：2D 网格，每格一个细胞或空
2. 能量守恒：动作消耗能量，食物提供能量，归零即死
3. 读取：只能读相邻 N 格的原始数值（N 越小越好）
4. 写入：只能改写相邻空格的数值
5. 连接：相邻细胞可绑定成刚体
6. 收缩：绑定细胞间距可缩短
```

六条规则。感知、运动、繁殖、身体、神经——全部在这六条之上涌现，而非被定义。

## 与"原语太低"的矛盾

| 原语太低 | 原语太高 |
|---------|---------|
| 搜索空间无限大 | 行为被预设，无涌现 |
| 盲搜永远搜不到 | 不算真正进化 |

**LLM 变异是解这个矛盾的关键**：原语可以放得很低（因为 LLM 能理解组合语义），但搜索不是盲的。传统 GA 需要原语高（否则搜不到），LLM 进化允许原语低——这打开了涌现的天花板。
