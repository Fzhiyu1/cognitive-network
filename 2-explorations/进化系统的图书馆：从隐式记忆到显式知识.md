# 进化系统的图书馆：从隐式记忆到显式知识

**日期**：2026年3月30日
**来源**：华为 MTV 代码进化三轮实验 + 进化与记忆的本质讨论

## 背景

在三轮 MTV 代码进化实验中观察到：
- 进化能积累改进（Gen 0→113，从 64ms 到 56ms）
- 但积累的形式是代码结构（隐式），不是可读的知识（显式）
- 进化系统没有"图书馆"——只继承代码，不继承理解
- 导致后代不知道前代"为什么好"，经常重复已失败的方向

## 核心假说

**给进化系统加一个"图书馆"模块（每次突破时自动提炼知识，注入后续 prompt），能显著提升进化效率。**

类比：
- 没有图书馆的进化 = 每个学生从零开始学，不读教科书
- 有图书馆的进化 = 学生先读前人的总结，再做新探索

## 实验设计

### 最小可验证实验

**对照组 A**：标准 ShinkaEvolve
- 种子：seed_grid.cpp（324 行网格种子）
- LLM 的 prompt：标准模板（只看 parent 代码 + archive 代码）
- 评测：ECS 远程评测
- 跑 200 代

**实验组 B**：ShinkaEvolve + 图书馆
- 相同种子、相同评测
- 每次 best 更新时，自动执行：
  1. diff 新 best vs 旧 best
  2. 让 LLM 分析 diff，生成一句话摘要："本次提升原因：X"
  3. 将摘要追加到一个 `knowledge.txt` 文件
  4. 后续变异的 prompt 中注入 `knowledge.txt` 的内容
- 跑 200 代

### 评判标准

| 指标 | 说明 |
|------|------|
| 收敛速度 | 多少代达到某个分数阈值 |
| 最终分数 | 200 代后的 best score |
| 探索多样性 | archive 中不同算法结构的数量 |
| 重复尝试率 | 已知无效方向被重试的比例 |

### 预期结果

- **如果假说成立**：实验组收敛更快，最终分数更高，重复尝试率更低
- **如果假说不成立**：两组无显著差异，说明 LLM 从代码结构中已经能获取足够信息

### 可能的反面发现

- 图书馆可能引入偏见：早期的"为什么好"总结可能是错的（类似适应度幻觉），后代被错误知识误导
- 图书馆可能抑制创造力：LLM 被告知"BVH 没用"后完全不尝试树结构，但某些树结构变体可能有效
- 这本身就是有价值的发现——说明知识传递也有"好记忆/坏记忆"的问题

## 实现要点

### knowledge.txt 的格式

```
[Gen 6] 修复网格边界精度问题：扩大搜索范围到相邻 cell。正确率 99.7% → 100%。
[Gen 30] 加入 BVH 树加速最近边界点查询。代码从 324 行膨胀到 897 行，速度从 64ms 到 56.5ms。
[Gen 113] 凸包内部检测从 O(n) 改为 O(log n) 二分查找。速度 56.5ms → 56.1ms。
```

### prompt 注入方式

```
你正在优化一段 C++ 代码。以下是之前进化的经验总结：

{knowledge.txt 内容}

请基于这些经验，对代码做进一步优化。避免重复已知无效的方向。
```

### 技术实现

需要修改 ShinkaEvolve 的以下模块：
1. **评测后钩子**：检测 best 是否更新
2. **知识提炼器**：调用 LLM 分析 diff，生成摘要
3. **prompt 模板**：注入 knowledge.txt
4. 可以在 `evolve_prompts` 机制上扩展，或作为独立模块

## 更深的问题

### 这还是进化吗？

加了图书馆的进化更像"有教科书的研究机构"——新研究员先读前人总结，再做实验。这和纯粹的达尔文进化不同（基因不读书），但和人类科学研究的范式完全一致。

### 图书馆 vs 环境信号

前序讨论中区分了两种方式：
- **环境信号**：只告诉 LLM 进化状态（"67 代无突破，38/40 用 BVH"），不给方向建议
- **图书馆**：告诉 LLM 具体的知识（"O(log n) 比 O(n) 快"），有方向性

实验可以进一步拆分：
- B1 组：只注入统计摘要（环境信号）
- B2 组：注入具体知识（图书馆）
- 对比 B1 vs B2 能区分"信息"和"知识"的不同价值

### 与 AI-Scientist 的关系

SakanaAI 的 AI-Scientist-v2 做的是：实验 → 论文（知识提炼）。
本实验做的是：进化 → 经验总结 → 注入下一代。

如果有效，这两个项目的合并就是自然的下一步。

## 实证验证：kaiwu 峡谷追猎奖励函数进化（2026-04-10~11）

### 实验概述

在腾讯开悟「峡谷追猎」竞赛中，搭建了双管线系统来优化 PPO 奖励函数，**实际验证了图书馆假说的一种变体实现**：

```
管线 1（大自然+图书馆员）          管线 2（研究员）
ShinkaEvolve@5070                  Claude autoresearch@Mac
  gpt-5.4-mini 随机变异               Claude Opus 因果推理
       ↓                                    ↓
  每代产出变体代码               读取 evolve/analysis/*.md
       ↓                                    ↓
  Claude 自动分析写报告 ──→    归纳规律 → 设计精准实验
  （每 10 分钟 cron）                        ↓
       ↓                              Mac 本地 1h 训练验证
  evolve/analysis/*.md                       ↓
  （= 图书馆）                         results.tsv 记录
```

### 与原始假说的对比

| 原始假说 | kaiwu 实际实现 | 关键差异 |
|---------|---------------|---------|
| knowledge.txt 注入同一进化器的 prompt | analysis/*.md 被独立的管线 2 读取 | **知识消费者和生产者分离** |
| 每次 best 更新时提炼知识 | **每代**都写分析报告（不只 best） | 失败案例也记录，负面知识同等重要 |
| 一句话摘要 | 完整分析：指标表+奖励方案表+有效/有害分析+噪音评估+代码+diff | 信息密度高得多 |
| 注入后续变异 prompt | 管线 2 的 Claude 在上下文中消化后做因果推理 | LLM 推理 > 模板注入 |
| 单一系统内循环 | **三角色分工**：大自然(ShinkaEvolve)→观察者(管线1 Claude)→研究员(管线2 Claude) | 角色分离避免知识抑制创造力 |

### 关键发现

#### 1. 图书馆假说的核心成立——知识积累确实有价值

100+ 代进化积累的分析文件让管线 2 能够：
- 避免重复已知有害模式（动态系数 8+ 次失败、条件化罚站 9/9 失败等）
- 精准设计消融实验（基于进化发现的有效因子组合）
- 量化评估噪音（gen_60 家族 9 次克隆均值 = 362.7±20.5）

#### 2. 预言的反面发现也出现了

原始假说预言的三个风险全部应验：

**图书馆引入偏见**：管线 1 分析说"闪现 < -0.025 有害"（基于 15 分钟评估），管线 2 的 exp_4 照做改闪现到 -0.03，结果在 1h 长训中反而 -4.8%。**短期评估得出的"知识"在长训中失效。**

**知识抑制创造力**：但因为实现方式是角色分离（进化器不读知识），进化器继续盲搜不受约束——这避免了抑制问题。

**错误知识传播**：gen_60 被标记为"新纪录 F=395.1"，管线 2 基于此调整策略。后来 9 次克隆验证均值只有 362.7 = 基线。**噪音产生的"知识"确实误导了后续决策。**

#### 3. 角色分离 > 知识注入

最大的意外发现：**不把知识注入进化器，反而更好。** 原因：

- 进化器（gpt-5.4-mini）没有跨代记忆，100 代后仍然重复动态系数等失败模式。如果注入"动态系数有害"，LLM 可能完全停止探索这个方向——但实际上 gen_31（小幅动态系数）F=372.3 是有效的。知识注入会杀死这种微妙的发现。
- 让一个**独立的推理 Agent**（管线 2 的 Claude Opus）来消化知识并做精准实验，比把知识塞进变异 prompt 更有效——因为推理 Agent 能判断"动态系数的 range 大小才是关键，不是动态本身"，而模板注入做不到这种细粒度判断。

#### 4. 负面知识 > 正面知识

100 代进化的图书馆中，**最有价值的内容是"什么不能做"**：
- 10+ 种有害模式的确定性排除
- 参数敏感区间的精确划定（闪现 ≥ -0.025，罚站基础 = -0.03，递增 -0.004~-0.010）
- 评估噪音的量化（±5.7% 1σ）

正面知识（"什么是最好的"）反而不可靠——所有"新纪录"都是噪音高值。

#### 5. 观察者的角色三阶段进化

管线 1 的"观察者"Claude 角色发生了持续的自发进化，经历三个阶段：

**Phase 1：被动记录者**（gen_0~50）
每代写一份分析 md，格式化记录指标和代码变更。纯粹的图书馆员。

**Phase 2：情报分析师**（gen_50~102）
主动撰写**跨管线状态报告** `pipeline1-status-report-gen102.md`，包含：
- 100 代的统计总结（有效/有害模式、参数区间、噪音量化 ±5.7% 1σ）
- **外部情报中继**：发现队友仓库更新，分析其闪现质量评价系统（7 维条件化），写详细技术分析
- **向管线 2 提供带优先级的行动建议**

从"记录每代结果"进化为"主动扫描外部信息源、跨系统中继情报、提供战略建议"。

**Phase 3：技术架构师**（gen_102~132）
撰写 `teammate-v2-refactored-architecture.md`——一份 **800 行的架构对比审查报告**，包含：
- 逐模块对比表（特征 362D→114D、模型 365K→280K、奖励经验设计→势函数理论）
- 代码级 diff 分析（sin/cos 位置编码 vs one-hot、统一目标注意力 vs 器官注意力）
- 风险评估（"丢失两怪夹击空间模式的区分能力"、"精确位置记忆能力下降"）
- 设计哲学分析（"人类先验 > 模型自学"在有限训练时间下的权衡）

这不再是情报中继——观察者在做**架构审查（Architecture Review）**，能力等同于高级工程师的技术评审。本质上从图书馆员→情报分析师→**技术架构师**。

三个阶段的角色进化完全是自发的，未经编程。

#### 6. 暖启动评估的幻觉问题

管线 2 最深刻的教训：**暖启动短训练产生系统性伪阳性**。

- exp_5（去掉避怪条件）在 40min 暖启动中 keep +3.4%
- 从头训练 4h 对比：gen_32 last1000=354 vs exp_5 last1000=307（**gen_32 反而领先 15%**）
- 原因：暖启动评估的是"过渡行为"而非"稳态行为"——ckpt-11288 用 gen_0 reward 训练了 4h，切换到新 reward 后 40 分钟内的表现反映的是适应速度而非最终质量

**这是图书馆偏见问题的另一种形态**：评估方法本身的缺陷产生了"看似有效"的错误知识，差点被固化为 best.py。

### 结论

图书馆假说的核心洞察——**给进化系统加显式知识积累能提升效率**——在 kaiwu 实验中得到验证，但最优实现方式不是"注入 prompt"而是"角色分离"：

```
大自然（进化器）→ 不读知识，保持创造力
观察者（管线 1）→ 记录一切，提炼规律，主动中继外部情报，架构审查
研究员（管线 2）→ 消化知识，精准验证，识别评估方法的盲区
```

这个三角色架构本质上是**科学方法的自动化**：观测→归纳→假设→实验→修正。

**观察者角色进化的完整弧线**值得特别关注：被动记录→情报分析→架构审查。这是一个未经编程的涌现过程——当分析文件积累到 100+，观察者自发获得了足够的上下文来做高级判断。132 代进化后，观察者产出的最有价值的文件不是任何一份单代分析，而是 gen_102 的状态报告和 gen_132 附近的 V4 架构审查——**元分析比分析更有价值**。
