# 进化系统的图书馆：从隐式记忆到显式知识

**日期**：2026年3月30日
**来源**：华为 MTV 代码进化三轮实验 + 进化与记忆的本质讨论

## 背景

在三轮 MTV 代码进化实验中观察到：
- 进化能积累改进（Gen 0→113，从 64ms 到 56ms）
- 但积累的形式是代码结构（隐式），不是可读的知识（显式）
- 进化系统没有"图书馆"——只继承代码，不继承理解
- 导致后代不知道前代"为什么好"，经常重复已失败的方向

## 核心假说

**给进化系统加一个"图书馆"模块（每次突破时自动提炼知识，注入后续 prompt），能显著提升进化效率。**

类比：
- 没有图书馆的进化 = 每个学生从零开始学，不读教科书
- 有图书馆的进化 = 学生先读前人的总结，再做新探索

## 实验设计

### 最小可验证实验

**对照组 A**：标准 ShinkaEvolve
- 种子：seed_grid.cpp（324 行网格种子）
- LLM 的 prompt：标准模板（只看 parent 代码 + archive 代码）
- 评测：ECS 远程评测
- 跑 200 代

**实验组 B**：ShinkaEvolve + 图书馆
- 相同种子、相同评测
- 每次 best 更新时，自动执行：
  1. diff 新 best vs 旧 best
  2. 让 LLM 分析 diff，生成一句话摘要："本次提升原因：X"
  3. 将摘要追加到一个 `knowledge.txt` 文件
  4. 后续变异的 prompt 中注入 `knowledge.txt` 的内容
- 跑 200 代

### 评判标准

| 指标 | 说明 |
|------|------|
| 收敛速度 | 多少代达到某个分数阈值 |
| 最终分数 | 200 代后的 best score |
| 探索多样性 | archive 中不同算法结构的数量 |
| 重复尝试率 | 已知无效方向被重试的比例 |

### 预期结果

- **如果假说成立**：实验组收敛更快，最终分数更高，重复尝试率更低
- **如果假说不成立**：两组无显著差异，说明 LLM 从代码结构中已经能获取足够信息

### 可能的反面发现

- 图书馆可能引入偏见：早期的"为什么好"总结可能是错的（类似适应度幻觉），后代被错误知识误导
- 图书馆可能抑制创造力：LLM 被告知"BVH 没用"后完全不尝试树结构，但某些树结构变体可能有效
- 这本身就是有价值的发现——说明知识传递也有"好记忆/坏记忆"的问题

## 实现要点

### knowledge.txt 的格式

```
[Gen 6] 修复网格边界精度问题：扩大搜索范围到相邻 cell。正确率 99.7% → 100%。
[Gen 30] 加入 BVH 树加速最近边界点查询。代码从 324 行膨胀到 897 行，速度从 64ms 到 56.5ms。
[Gen 113] 凸包内部检测从 O(n) 改为 O(log n) 二分查找。速度 56.5ms → 56.1ms。
```

### prompt 注入方式

```
你正在优化一段 C++ 代码。以下是之前进化的经验总结：

{knowledge.txt 内容}

请基于这些经验，对代码做进一步优化。避免重复已知无效的方向。
```

### 技术实现

需要修改 ShinkaEvolve 的以下模块：
1. **评测后钩子**：检测 best 是否更新
2. **知识提炼器**：调用 LLM 分析 diff，生成摘要
3. **prompt 模板**：注入 knowledge.txt
4. 可以在 `evolve_prompts` 机制上扩展，或作为独立模块

## 更深的问题

### 这还是进化吗？

加了图书馆的进化更像"有教科书的研究机构"——新研究员先读前人总结，再做实验。这和纯粹的达尔文进化不同（基因不读书），但和人类科学研究的范式完全一致。

### 图书馆 vs 环境信号

前序讨论中区分了两种方式：
- **环境信号**：只告诉 LLM 进化状态（"67 代无突破，38/40 用 BVH"），不给方向建议
- **图书馆**：告诉 LLM 具体的知识（"O(log n) 比 O(n) 快"），有方向性

实验可以进一步拆分：
- B1 组：只注入统计摘要（环境信号）
- B2 组：注入具体知识（图书馆）
- 对比 B1 vs B2 能区分"信息"和"知识"的不同价值

### 与 AI-Scientist 的关系

SakanaAI 的 AI-Scientist-v2 做的是：实验 → 论文（知识提炼）。
本实验做的是：进化 → 经验总结 → 注入下一代。

如果有效，这两个项目的合并就是自然的下一步。
