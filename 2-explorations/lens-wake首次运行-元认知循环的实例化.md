# lens+wake 首次运行：元认知循环的实例化

**讨论者**：fangzhiyu × Claude Opus 4.7
**日期**：2026-05-03
**背景**：[[形状记忆系统]] V0 部署完成（lens 代理 + wake 长上下文记忆层 + DeepSeek 1M），首次在真实 Claude Code 会话中验证。

---

## 工程现状

`lens` 是一个 Anthropic API 透明代理，跑在 localhost:8765：

```
Claude Code (ANTHROPIC_BASE_URL=http://localhost:8765)
    ↓
lens (插件链：strip 旧记忆 → 调 wake 拿新记忆 → 注入 system 块)
    ↓ HTTPS_PROXY=121.4.45.119:31272 防封
api.anthropic.com
```

`wake` 是 KB 全量注入 DeepSeek 的 daemon，给定 query 生成相关记忆文本。

`lens` 的 `wake_memory` 插件每轮干两件事：
1. `stripped N old` — 剥掉上一轮注入的 `[当前相关记忆]...[/当前相关记忆]` 块
2. `injected M chars new` — 拿 wake 当前召回写进 system

效果：每轮 body 体积稳定在 47-49 万字节（不累积），相邻轮波动十几 KB（=新对话+新注入）。

## 第一次实际运行的事件

### 事件序列

1. 用户问："记忆里 比如 多层有损压缩 你能看见吗"
2. wake 注入了 [[多层有损压缩]] 的拓扑信息（50条入边、簇大小、占比）
3. **AI（我）幻觉了**：回答说"我看到有损压缩，但没看到'多层有损压缩'"
4. 用户追问："你现在还能看见 有损压缩吗"
5. AI 回看注入内容 → 发现自己幻觉 → 公开修正

### 这件事真正的意义

这次幻觉不是 bug，是 **系统第一次完整工作的证据**。把它拆开看：

| 步骤 | 系统组件 | 作用 |
|------|---------|------|
| 注入拓扑信息 | wake → lens → system 块 | 提供外部锚点 |
| AI 幻觉 | LLM 自然属性 | 失败发生（必然会发生） |
| 用户追问 | 人 | 触发对照测试 |
| AI 回看注入 | LLM + 长上下文 | 反向追溯 |
| 修正 | LLM 输出 | 失败被显化为可输出的判断 |

**关键点**：如果只是 wake 召回得准、AI 答得对——那只是一个"有效的记忆系统"。但当 AI 答错、被用户追问、然后能反向追溯到注入的原文识别自己的幻觉——这是一个**元认知系统**在工作。

记忆系统的成功标准是 recall accuracy。元认知系统的成功标准是 [[失败可见性]]。

## 三件套缺一不可

让幻觉被识别，需要三件事同时在场：

- **外部锚点**：wake 注入的内容写在 system prompt 里，不依赖 AI 的内部状态
- **对照测试**：用户的追问强制 AI 把内部声明拿去比对锚点
- **反向追溯**：AI 能回看已注入的内容并诚实承认差异

这正是 [[校准的不可外包性]] 在输出端的对偶——判断"我刚才在不在幻觉"也不能纯靠 AI 自己完成。

## lens log 作为系统观测层

`/tmp/lens.log` 暴露了每一轮的插件行为：

```
02:35:11 stripped 0 old, no new recall      ← 无关问题，wake 不召回
02:35:31 injected 372 chars new             ← "无限空间之王/有损压缩"那轮
02:35:56 injected 486 chars new             ← "元认知系统"那轮
02:36:17 injected 427 chars new             ← "log 怎么看"那轮
```

log 本身就是元认知层的另一面：人能看到系统在召回什么、剥离什么、注入什么。这与 AI 端的"看见自己在幻觉"是同一件事——把黑盒打开。
