# 程序化 UI 还原闭环：从亚像素对齐实践到方法论

**讨论者**：fangzhiyu & Claude Opus 4.6
**日期**：2026-04-08
**背景**：在车载 KTV 2092×1740 新断点适配中，需要将 Figma 设计稿精确还原到代码。前一天的多模态 LLM 实验证明视觉对比有 2-3px 噪声地板且方向不可靠，本次探索出一条程序化闭环路径，实现了 0.02px 级别的对齐精度。

---

## 问题起点

设计还原的核心矛盾：
1. **人工对比低效** — 逐像素肉眼扫视，容易遗漏，无法量化
2. **多模态 LLM 不够精确** — [[噪声鲁棒性与天花板|基线噪声 2-3px]]，方向判断经常反转（详见 [[多模态LLM像素级UI对比能力实验]]）
3. **SSIM/LPIPS 只给分数** — 知道"有差异"但不知道"差在哪、改什么"

需要一种方法：既能精确到亚像素，又能归因到具体 CSS 属性。

## 闭环架构

最终跑通的系统由三个数据源构成闭环：

```
Figma MCP (get_node_info)     →  设计真值（absoluteBoundingBox, style）
       ↓ × ratio 缩放
    期望值表（精确到 0.1px）
       ↓ 对比
CDP webview_evaluate           →  渲染真值（getBoundingClientRect, getComputedStyle）
       ↓ 发现偏差 & 归因
    修改 CSS 变量 / Vue 模板
       ↓ HMR 热更新
CDP webview_evaluate           →  重新测量 → 闭环验证
```

### 数据源 1：Figma MCP — 设计真值

通过 `get_node_info(nodeId, depth=5)` 获取 Figma 节点的精确数据：
- `absoluteBoundingBox`：每个元素的 x/y/width/height（全局坐标）
- `style.fontSize`、`style.lineHeightPx`：排版参数
- `cornerRadius`：圆角
- `fills`、`strokes`：颜色

关键：通过计算相对坐标（子元素 xy - 父元素 xy）得到精确的内边距、间距、偏移量。

### 数据源 2：统一缩放比

```
ratio = targetWidth / designWidth = 1920 / 2092 = 0.9178
```

所有 Figma 值乘以 ratio 即为 CSS 期望值。消除人工换算误差。

### 数据源 3：CDP webview_evaluate — 渲染真值

通过 `webview_evaluate` 在模拟器 WebView 中执行 JavaScript：

```javascript
const el = document.querySelector(selector);
const rect = el.getBoundingClientRect();
const style = getComputedStyle(el);
// → 精确到 0.01px 的渲染坐标和计算样式
```

与期望值逐一对比，偏差立刻可见。

## 实战过程：QrLoginCard 登录卡片

### 第一轮：结构性偏差（10+ px）

| 问题 | 偏差 | 根因 |
|------|------|------|
| "扫码登录"文字偏上 11.7px | y: 166.4 vs 178.1 | `justify-between` 把文字推到容器底部 |
| VIP 底部区域过高 | h: 209.2 vs 97.3 | 子智能体混淆了"功能入口区高度"和"VIP 信息条高度" |

修复：`justify-between` → `gap-[29.4px]`，VIP 底部高度修正。

### 第二轮：排版偏差（3-5 px）

| 问题 | 偏差 | 根因 |
|------|------|------|
| 标题行高偏大 3.6px | lh: 55px vs 51.4px | `leading-normal`（1.5×）vs 设计稿实际比例（1.4×） |
| VIP 描述偏下 4.3px | y: 341 vs 337 | `--ul-qr-card-bottom-text-gap` 7.2px vs 设计稿 3.7px |

修复：显式 `line-height: 1.4`，调整 gap 变量。

### 第三轮：定位偏差（1-2 px）

| 问题 | 偏差 | 根因 |
|------|------|------|
| VIP 标题偏下 2.2px | y: 299.6 vs 297.4 | `items-center` 居中 vs 设计稿偏上对齐 |
| 按钮偏下 1.9px | y: 302 vs 300.1 | 同上 |

修复：`items-center` → `items-start` + 精确 `padding-top: 12.8px`，按钮 `margin-top: 2.8px`。

### 第四轮：亚像素精调（< 1 px）

| 问题 | 偏差 | 根因 |
|------|------|------|
| VIP 容器 y 偏下 0.4px | y: 284.9 vs 284.5 | `padding-bottom: 17.7px` 略大 |

修复：`padding-bottom: 17.3px`。

### 最终精度

| 元素 | 设计值 | 渲染值 | 偏差 |
|------|--------|--------|------|
| "扫码登录" y | 178.1 | 178.08 | **0.02px** |
| 副标题 y | 233.8 | 233.75 | **0.05px** |
| VIP 容器 y | 284.5 | 284.63 | **0.13px** |
| VIP 标题 y | 297.4 | 297.42 | **0.02px** |
| VIP 描述 y | 336.8 | 337.22 | **0.42px** |
| 按钮 y | 300.1 | 300.22 | **0.12px** |

全部元素偏差 **< 0.5px**。

## 与多模态实验的对比

| 维度 | GPT-5.4 多模态看图 | Figma MCP + CDP 闭环 |
|------|-------------------|---------------------|
| 精度 | 2-3px [[噪声鲁棒性与天花板\|基线噪声]] | **0.02px** |
| 方向判断 | 经常反向 | 数值精确，无歧义 |
| 归因能力 | "偏左约 4px" | "line-height 1.5→1.4，差 3.6px" |
| 可自动化 | 需截图 + 调 API | 全程 MCP/CDP 工具调用 |
| 修复闭环 | 不可行（方向不可靠） | **修改 → 热更新 → 重新测量 → 收敛** |

这正是 [[多模态LLM像素级UI对比能力实验]] 中预判的"混合方案"——只不过定量部分不是 SSIM/LPIPS，而是直接读 DOM 坐标，更简单也更精确。LLM 的角色从"看图猜差异"变成了"分析数值偏差的根因并决定改哪个 CSS 属性"。

## 核心洞察

### 1. [[设计还原闭环|闭环]]的关键是两端都程序化

设计端（Figma MCP）和渲染端（CDP）都能输出精确数值，LLM 只需要做中间的"理解 + 决策"，不需要做"感知"。把感知从 LLM 卸载到程序化工具，精度从 2-3px 跃升到 0.02px。

### 2. 偏差有层级结构

从 10+ px 的结构性错误（容器类型搞混）→ 3-5px 的排版参数（行高、间距）→ 1-2px 的对齐策略（center vs start + padding）→ 0.4px 的亚像素微调。每一层的修复方法不同，不能跳级。

### 3. [[可观测性]]决定修复速度

能实时测量（webview_evaluate），就能实时验证。改一行 CSS 变量，2 秒后就知道偏差从 2.2px 变成了 0.02px。这种 [[可观测性]] 使得"像素级自动修复循环"从"目前不可行"变成了实际可操作的流程。

### 4. 缩放比是信任锚点

`ratio = targetWidth / designWidth` 是整个系统的信任锚点。只要这个比例正确，所有 Figma 值都能精确映射到 CSS 值。不需要逐元素目视确认。

## 适用场景

| 场景 | 推荐方案 |
|------|---------|
| 新断点全量适配 | 本闭环（Figma MCP + 缩放比 + CDP 验证） |
| 微调已有样式 | CDP webview_evaluate 直接测量 + 对比 |
| 快速筛查差异模块 | 多模态 LLM 扫一遍（>3px 标记），再用闭环精修 |
| 跨团队设计 QA | 导出期望值表，CI 中用 CDP 自动回归 |

## 后续方向

1. **自动化脚本** — 将"读 Figma 节点 → 计算期望值 → CDP 测量 → 输出差异表"封装为 MCP 工具，一键生成对齐报告
2. **CI 回归** — 每次构建后自动跑 CDP 测量，与期望值表对比，超过 1px 阈值报警
3. **多断点矩阵** — 同一套 Figma 节点 × 多个 ratio，批量验证所有断点
4. **与多模态互补** — 程序化闭环处理已知元素的精确对齐，多模态 LLM 处理"这个布局看起来对不对"的定性判断
