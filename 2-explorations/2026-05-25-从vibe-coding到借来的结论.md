# 从 vibe coding 到借来的结论

**讨论者**：fangzhiyu & Claude（Opus 4.7）
**日期**：2026-05-25
**背景**：起点是一句吐槽——"vibe coding 快把程序员逼成测试工程师了，为什么"——一路推到理解本身的传递性问题

---

## 1. 起点：生成变便宜，验证没有

vibe coding 把"写代码"压到接近零成本，但没动"确认代码对不对"。过去验证是写作的副产品（一行行写的过程在脑里建了"为什么对"的模型），抽走"写"这一步后，验证从副产品变成主任务。而"不看实现、只看行为地确认系统正确"——这就是测试工程师的定义。

底层是 P/NP 式的不对称：产出一个解 和 验证一个解 的成本曲线不同。LLM 把前者压到零，后者纹丝不动，瓶颈必然平移到正确性。这正是 fangzhiyu CLAUDE.md 那套成本模型的推论：`工时→0` 后，活下来的是「审核带宽 + 正确性风险」。

## 2. AI 应用工程师 = 规格所有者 + 正确性担保人

角色不是"产品 + 测试"的并列，是同一根轴的两端在时间上的两次投影：事前把"对"定义出来（spec），事后确认产物命中（验证）。关键：**验证质量的上限被需求表达的清晰度锁死**——说不清"对"是什么，就只能"看着差不多"。

"全栈/广"不是优点是被逼的：AI 包了每一层的"写"，剩下全是跨层接缝处的判断，而接缝天然跨层。这个角色门槛不是降了是升了——它把工程里最难自动化的两件事（把模糊意图精确化、判断正确性）从写代码过程里隐藏的，变成必须显式独立交付的核心产物。详见 [[判断力位]]。

## 3. 自动化测试能替代验证吗：oracle 难题

不能替代核心，只能替代体力。任何测试都要回答"输出对不对"，决定"对"的那个 oracle（判定标准）不在自动化范围内——它来自"你知道应该是什么样"。

让 AI 自写测试自发现问题 = 让它同时当运动员和裁判：oracle 是它自己对需求的理解，于是只能抓"实现 vs 它自己的理解"之间的低级矛盾，抓不到"它理解错了你的意图"——而后者正是 vibe coding 翻车主因。测试还会**继承编写者的盲点**：同一 AI 用同一理解先写码再写测试，错在哪测试就在哪一起假设错，两边握手言和绿灯通过，安全感是假的。

可操作折中：你只写少数几条不可妥协的 oracle（核心链路、数据不丢、不崩），其余体力外包给 AI。**保留权威，外包体力。** 验证强度应匹配赌注大小——真不在乎的项目让 AI 自测是合理的；危险的是"不上心"和"其实很重要"错配。

## 4. 转折：老生常谈为何今天才懂

"AI 时代判断力很重要"是句被说烂的话，但 fangzhiyu 说今天理解得比以前深，觉得奇怪。

解释：这句话是**压缩过的结论**，是一长串推导的最后一行——一片叶子。以前听到是在"读别人 vibe coding 出来的产物"：能编译（听着对），但没有背后的心智模型。今天不同，是因为自己把推导树**重新长了一遍**（成本模型→生成便宜→瓶颈平移→oracle→判断不可外包）。

字面没变，变的是你和它的关系：从读者变成作者。这就引出核心概念 [[借来的结论]]：**理解不能被传递，只能被重新推导；老生常谈感正是"持有叶子但没走过树"的落差。** 触发重新推导需要燃料——而 fangzhiyu 前几天撞 vibe coding 的墙，就是攒下的燃料。

## 5. 反驳与修正：那理解怎么"传"给 AI 的？

fangzhiyu 的尖锐反问：理解不可传递，可 AI 只吃文本却懂了，这不是反例吗？

修正后它是最强正例：我们没传递理解，我们给的是**语料**（海量叶子）。AI 在 next-token 损失压力下被逼着重建生成函数——**训练就是大规模的重新推导**，梯度是它的"撞墙"。差别不是"文本 vs 非文本"（两边都是文本），是**体量 + 压力**：人听一遍金句是被动接收零压力、得 1 片叶子无理解；AI 见几万片相关叶子被损失函数强制重建结构。人脑版的训练，就是亲身摩擦。

所以"传递"这个动词本身错了：文本不是管道，是**催化剂**。文本 + 接收方已有燃料 + 接收方亲自跑推导 = 理解被重新生成，不是被搬运。

## 6. 推到教学：剪影可复制，纹路不可复制

fangzhiyu 提出叶子类比并要求理性分析："我只给别人一片叶子，想看就看，想理解得看叶子上的纹路，再拿自己的叶子对比。"

修正出关键结构错误：**纹路不在你递出的叶子上**。结论是推导树压缩后的产物，压缩把纹路碾平了——你递出的是**剪影/压平的标本**，盯着看一万年也看不出纹路。正确版：

- 你能递的只有**轮廓**；纹路看不到，只能自己重新长出来
- "对比"要改成"照着轮廓重新长一片"：我的剪影成了目标形状，你用自己的种子养料长新叶，**长出的纹路是你的**
- 理解完成的标志：轮廓对上了，但内部脉络是你本地生成的——轮廓吻合制造了"传过来了"的错觉
- 前置门槛：得先有相邻叶子可映射，零经验则催化剂落在湿木头上点不着

**信息可传输（剪影可复制），理解不可传输（纹路不可复制）。**

回到"如何让别人理解"：你无法让别人理解，只能让他自己重新长。能做的三件都不是"递更大的叶子"——给清晰轮廓（必要但不够）、制造压力或定位他已有的燃料（**好问题胜过好解释**，苏格拉底法本质是故意不给叶子逼你长）、认命于长叶子这步是他的。**教不是传输叶子，是催化对方重新长一片。**

---

*核心链条：生成便宜→验证成瓶颈→判断/oracle 不可外包→理解不可传递只能重新推导→训练是大规模重新推导→教是催化重新生长。一句话：能被搬运的只有产物的轮廓，结构永远得在本地重新长。*
