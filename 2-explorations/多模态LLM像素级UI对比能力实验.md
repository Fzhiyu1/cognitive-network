# 多模态 LLM 像素级 UI 对比能力实验

**讨论者**：fangzhiyu & Claude Opus 4.6 + GPT-5.4
**日期**：2026-04-07
**背景**：在车载 KTV 3xl 断点适配中，尝试用 GPT-5.4 多模态能力自动分析 Figma 重影叠加图，验证其作为像素级 UI 对比工具的可行性。

---

## 实验动机

设计还原度验证的痛点：程序化对比（SSIM/LPIPS）能给出数值差异，但无法解释"为什么差"和"改哪个 CSS 属性"。人工逐像素扫视效率低。假设多模态 LLM 能填补这个缺口——看懂重影图，输出结构化的 CSS 修改建议。

## 实验设计

用浏览器开发者工具将 Figma 设计稿半透明叠加在渲染页面上，截图后通过 API 发送给 GPT-5.4 分析。

### 实验 1：放大倍率对比

同一张基准图，分别以 1x/2x/4x/8x 放大后送入模型。

| 倍率 | 标题偏左报告 | 换算回原始 | 方向一致性 |
|------|------------|-----------|----------|
| 1x | 4px | 4px | 一致 |
| 2x | 6px | 3px | 一致 |
| 4x | 20px | 5px | 一致 |
| 8x | 18px | 2.3px | 图标方向反了 |

**结论**：放大无帮助。1x 原图最准，放大后像素值膨胀且 8x 时方向判断出错。

### 实验 2：对照实验（加入已知偏移）

对同一个 [[SongCard]] 中间列组件，分三组：
1. **对齐状态**（用户确认对齐）→ 模型报告偏左 2px
2. **无偏移**（代码原始值）→ 模型报告偏左 8px
3. **+10px 右偏移**（padding-left 增加 10px）→ 模型报告偏左 8px

**关键发现**：加了 +10px 向右偏移后，模型仍然报告"偏左"，方向判断完全错误。

### 实验 3：小元素测试（已点按钮）

给已点按钮加 margin-left: 10px（向右偏移），模型报告"整体向下偏移约 8px"——方向再次判断错误。

### 实验 4：增量感知测试

- 基准（无偏移）→ 模型报 8px
- 加入 +5px left / +3px top → 模型报 4px
- 偏移量确实减半，说明模型**能感知到差异的相对变化**

### 实验 5：reasoning effort 对比

同一张图用不同 reasoning effort：
- 默认：偏左 3px、偏上 2px
- xhigh：偏上 6px、字号偏大 2px（方向和默认不一致）

**结论**：xhigh 更详细但不一定更准确，且方向判断可能翻转。

## 核心结论

### 能做什么
1. **检测是否存在差异** — 对齐的图报 2-3px（[[噪声鲁棒性与天花板|基线噪声]]），有差异的报 6-8px+，可区分
2. **感知差异的相对变化** — 修改后差异减小，模型报告的数值也减小（[[可观测性]]的一种体现）
3. **识别系统性偏移** — 如果所有元素偏同一方向，能归因到父容器
4. **提供修改方向的参考** — 虽然不精确，但给出了"哪些属性可能需要调"

### 不能做什么
1. **准确判断偏移方向** — 向右偏了说偏左，向右偏了说偏下，方向不可靠
2. **给出精确像素值** — 基线噪声 2-3px，实际值和报告值经常差 2-5px
3. **替代人工确认** — 最终对齐判断必须靠人眼
4. **放大图片不提升精度** — 反而降低准确度

### 基线误差
模型对完全对齐的图片仍会报告 2-3px 的偏移，且**系统性偏向报"偏左"**。

## 适用场景

| 场景 | 推荐方案 |
|------|---------|
| 快速筛查"哪些模块有差异" | 多模态 LLM 扫一遍，>3px 的标记出来 |
| 判断修改前后是否改善 | 对比两张图的报告数值（相对变化可靠） |
| 确定精确偏移方向和量 | 人工重影对比 + 开发者工具量测 |
| 像素级自动修复循环 | 目前不可行，方向判断不可靠 |

## 后续方向

1. **程序化像素差分** — 截图对齐后逐像素相减，输出偏移量热力图，精度远高于多模态视觉
2. **SSIM + CSS diff 组合** — design-verify MCP 已有能力，精确到属性级别
3. **混合方案** — 程序化定量 + LLM 定性（解释差异原因、建议 CSS 属性），类似 [[三口径Token观]] 的多视角互补思路

---

*多模态 LLM 能感知 UI 差异的存在和变化趋势，但无法可靠判断偏移方向，不能替代人工做像素级精确对齐。*
