# LLM 代码进化实战：从 81ms 到认知边界

**日期**：2026年3月29-31日
**来源**：华为软件精英挑战赛 MTV（最小平移向量）问题，使用 ShinkaEvolve 进行三轮代码进化

## 一、背景

华为 2026 软件精英挑战赛初赛，要求计算两个简单多边形的最小平移向量（MTV）。给定多边形 A、B，对 10000 个查询点，每个点计算一个平移向量使 A 和平移后的 B 不重叠。

评分 = 正确率 × 速度分。预处理限时 1 秒（不计分），查询速度计分。

使用 ShinkaEvolve（SakanaAI 的 LLM 驱动代码进化框架），以 evolved_v7（openevolve 上一轮的最优解）为种子进行进化。

---

## 二、三轮进化数据

### 第一轮：5070 Docker 评测（mtv_online）

```
种子: evolved_v7 (730 行, Minkowski 差 + 线性扫描)
评测: 5070 WSL Docker (AMD Ryzen 9700X, GCC 11, c++17)
结果: 1232 代, $50, Best=Gen 577 (73ms ECS)
线上: v7=338k, Gen 577=329k-336k (更差!)
```

**发现**：进化在 5070 Docker 上优化了 Morton 排序、边排序等 cache 优化，但这些优化在线上 CPU 上反而更慢。评测噪声 IQR=8ms，导致进化优化噪声而非信号。

### 第二轮：华为云 ECS 评测（mtv_ecs）

```
种子: evolved_v7
评测: 华为云 ECS (Intel Ice Lake, 1核2G, GCC 11, c++11→c++17)
结果: 577 代, $50, Best=Gen 577 (73ms)
线上: Gen 516=329k-336k (仍然比 v7 差)
```

**发现**：
1. **预处理不计分** — Interactor 的 total time 只算查询阶段，预处理有 1 秒随便用
2. **I/O 占一半时间** — scanf/printf 6ms/case, 纯算法才 4ms/case
3. **ECS 噪声极低** IQR=0.3ms（5070 的 1/20），但 ECS 优化仍不迁移到线上

### 第三轮：网格种子 + 快速 I/O（mtv_v3）

```
种子: seed_grid.cpp (324 行, 网格索引 + getchar_unlocked)
评测: ECS 远程, c++17, ref_solution 对比正确率
结果: 312 代, $31, Best=Gen 196 (55.9ms)
线上: Gen 113=73k (崩溃! v7=338k)
```

**发现**：
1. 快速 I/O 确实有效（83ms→55ms）
2. 但进化又趋同到 BVH，网格框架没保住
3. **线上 73k 是致命问题** — practice 100% 正确但线上大面积出错
4. 原因未查明（可能是复杂多边形上的算法 bug）

## 三、关键发现

### 1. 进化的超能力 = 致命缺陷

进化会完美适应你给它的环境。如果环境是真实的，这是产品；如果环境是模拟的，这是幻觉。

```
ECS (Ice Lake) 上进化 → 完美适应 Ice Lake 的 cache
线上 (未知 CPU) 运行 → 适应度幻觉，反而更差
```

没有灰色地带。差一个 CPU 型号就足以让进化产物失效。

### 2. 进化趋同性

三轮进化，三个不同的种子（v7/极简/网格），结果都趋向 BVH + 树结构。

这不是因为 BVH 是最优解，而是因为 BVH 是 LLM 训练数据里最常见的空间加速方案。就像自然界的趋同进化——水里的动物都长成鱼形，不是因为鱼形最优，而是因为流线型最容易进化出来。

**搜索空间由 LLM 的知识决定，不由种子决定。**

### 3. 预处理不计分的杠杆

这个发现改变了整个策略方向。Interactor 的 total time 只算查询阶段（发送测试点到收到答案），预处理的 1 秒完全不计分。

```
空 preprocess (500ms busy wait) + 查询 → total time = 6ms (只算查询)
正常 preprocess + 查询 → total time = 8ms (同样只算查询)
```

这意味着可以在预处理中做任意重的预计算（光栅化查表、Voronoi 分区等），查询阶段只做 O(1) 查表。

### 4. I/O 是隐藏的大头

```
scanf/printf: ~6ms/case (I/O)  + ~4ms/case (算法) = 10ms
getchar_unlocked: ~2ms/case (I/O) + ~4ms/case (算法) = 6ms
```

快速 I/O 一项就省了 40% 时间。但之前的进化从未触碰 I/O 层——因为 I/O 代码在 EVOLVE-BLOCK 外面。

### 5. 只能爬坡不能跨谷（有争议）

进化在同一个算法框架内做微调（56ms→55.9ms），但无法跳到完全不同的框架（如查表方案）。

但这个结论有争议：full rewrite（50%）理论上可以跨谷，只是当前 LLM 的跳跃能力不够——编译失败率太高。随着 LLM 变强，跨谷能力可能提升。

**岛模型 + full rewrite = 进化的跨谷机制，但当前 LLM 是瓶颈。**

## 四、进化与记忆

### 进化的本质：有记忆的搜索

进化不只是搜索（随机搜索没有积累）。进化 = 搜索 + 积累。每一代的代码是所有前代知识的结构化总和。

```
随机搜索：尝试 → 丢掉 → 尝试 → 丢掉
进化：    尝试 → 保留好的 → 在好的基础上尝试 → 保留更好的
```

### 知识即结构

记忆不是"存在某处的数据"，是"载体本身的结构"。

| 系统 | 载体 | 知识存储形式 |
|------|------|------------|
| 大脑 | 突触连接 | 连接模式 |
| 基因 | DNA 序列 | 碱基排列 |
| 进化代码 | 源代码 | 代码结构 |
| DGD 矩阵 | 权重矩阵 | 权重分布 |

Gen 113 的 `insideConvexFast` 是一段"记忆"——它记住了"二分比线性快"。但这个知识以代码结构存在，不是声明式的。

### 好记忆 vs 坏记忆

- 好记忆 = 泛化（O(log n) 二分 → 任何 CPU 都快）
- 坏记忆 = 过拟合（Morton 排序 → 只在 Ice Lake 上快）

**区分方法只有一个：换环境试试。** 这就是动态测试集的价值。

### 进化系统缺图书馆

当前进化只继承代码（隐式知识），不继承理解（显式知识）。

```
大脑标本 ≠ 教科书
代码继承 ≠ 知识继承
```

如果每次突破后自动提炼"这次为什么变快了"，存成文字注入后续 prompt——进化就有了图书馆。

**这正是 AI-Scientist + ShinkaEvolve 合并后的形态。**

## 五、LLM 进化 ≠ 达尔文进化

| | 达尔文进化 | LLM 进化 |
|---|---------|---------|
| 变异 | 盲目随机 | **有意识的理解和推理** |
| 选择 | 环境筛选 | 评测筛选 |
| 积累 | 基因序列 | 代码结构 |
| 知识传递 | 只通过基因 | 代码 + prompt |
| 跨谷能力 | 极低 | 有（full rewrite），但受 LLM 能力限制 |

LLM 进化更像**自动化研究机构**：

```
LLM 变异器      = 研究员（读前人工作，尝试改进）
评测器          = 同行评审
岛模型          = 不同研究组
archive        = 期刊
全局状态注入    = 文献综述
```

**基因不思考，但 LLM 会。** 这使得 LLM 进化是一种全新的东西——有意识的变异 + 无意识的选择。

## 六、模拟器精度阶梯

模拟器不需要"足够真"，需要"在进化当前粒度上足够真"。

| 优化粒度 | 需要的环境真实度 |
|---------|--------------|
| 算法框架（Mink 差 vs 查表） | 随便，任何能跑的环境 |
| 数据结构（BVH vs 线性扫描） | 同架构就行 |
| 内存/cache 优化 | 几乎一样的 CPU |
| 指令级优化 | 完全相同的机器 |

进化会自动找当前最容易出分的层次。算法层有空间时，粗糙环境就够。算法层饱和后，进化转向 cache 层——这时环境不够真就出问题。

**早期用粗糙快速环境，晚期切真实环境。** 胚胎在子宫里发育，出生后面对真实世界。

## 七、未验证的假说

### 假说 1：图书馆能提升进化效率
- 对照实验已设计（见「进化系统的图书馆」探索文档）
- 核心：每次突破后提炼知识，注入后续 prompt

### 假说 2：环境信号注入能打破趋同
- 不告诉 LLM "试查表"，只告诉它 "38/40 用 BVH，37 代无突破"
- LLM 自己推导出应该换方向
- 按岛的停滞程度分级注入：停滞久的岛信号强，进步中的岛不加

### 假说 3：动态测试集能防止过拟合
- 固定集评分 + 随机集过滤
- 或 throughput 模式（持续流式评测，无固定测试集）

### 假说 4：预计算查表能突破 21ms
- 预处理时光栅化 NFP 边界到网格
- 查询变 O(1) 查表
- 但精度问题（ε=1e-4 vs 网格粒度）需要解决

## 九、核心教训

1. **进化不等于进步。** 本地分数涨了不代表线上涨。必须线上验证。
2. **评测环境 = 你在解的题。** 环境差一点，解的就是另一道题。
3. **LLM 进化的天花板是 LLM，不是进化框架。** 框架已经够用，LLM 的知识空间决定搜索范围。
4. **简单 > 复杂。** v7（730 行，线性扫描）线上 338k。Gen 113（931 行，BVH+网格+二分）线上 73k。
5. **理解评分规则比优化算法更重要。** "预处理不计分"这一个发现就改变了整个策略。
