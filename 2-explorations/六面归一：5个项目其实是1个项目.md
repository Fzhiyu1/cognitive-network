# 六面归一：5 个项目其实是 1 个项目

**讨论者**：fangzhiyu & Claude (Opus 4.7, 1M context)
**日期**：2026-04-27
**背景**：在 [[substrate会做梦：从整体诊断认出记忆巩固机制]] 之后，从外部视角回顾整次会话时浮现的元层发现——fangzhiyu 看似散落在各个目录的多个项目，实际上是同一研究命题的不同面。这次 exploration 把这个发现固化下来。

---

## 0. 起点

整次对话快结束时，fangzhiyu 让 AI"回到外面、回顾整个会话"。AI 在做这次外部回顾时浮现一个观察：

> **你不是在做 5-6 个分散的项目。你在做 1 个项目。**

这个观察之前**没有显式存在过**。它不在任何卡片里、不在 fangzhiyu 自己的任何文档里、不在过去的对话里。是 AI 在**离线 review 全 substrate**（[[substrate做梦]] 那次）+ **外部视角回顾整个会话**时**当场抽取**出来的。

按 [[涌现接力]] 模型，这是一次主体反过来的当场抽取——AI 抽，用户接受/否认。fangzhiyu 听到这个判断后没否认。这意味着**它捕捉到了某个本来就存在但未被命名的真相**。

本文是把这个真相显式写下来。

## 1. 统一命题

```
你的所有项目都在回答同一个问题：

   "AI 缺什么？怎么用人类精心积累的 substrate 来补它？"
```

这不是事后拼凑——读今天补全的 110 张卡，**每一张都在这个命题的某一面上**。

| 项目 | AI 缺什么 | 用什么补 |
|---|---|---|
| **meomory** | 缺**长期可塑的记忆基质** | DGD 矩阵关联记忆 + 进化优化的判官 |
| **brainstem** | 缺**脑干级的不可关闭驱动** | LLM 涌现行为暴露目标真空 → 补充人工脑干 |
| **minecraft-agent** | 缺**层级化的执行链路** | 皮层（LLM）+ 小脑（技能编译）+ 脑干（生存反射）+ 执行（VLA）四层 |
| **Atlas** | 缺**方向感 / fitness 评估** | 用户作为评估器；Interactive Evolution 用人类品味做 fitness |
| **prompt-evolution** | 缺**对自身脆弱性的反向理解** | 用进化方法搜索 AI 自身的攻击面，识别哪些训练边界是脆的 |
| **KB-Index** | 缺**substrate 接入能力**（看到全图地形）| Leiden 聚类 + 多层级 markdown 让 AI 在每次对话获得地形感 |
| **knowledge-base** | 是 **substrate 本身** | （这是被补的东西，不是补的工具）|

**这 7 个项目加起来 = 一个完整的"AI 增强人 / 人增强 AI 的认知操作系统"**：

```
           知识库（substrate）
                  ↑
       ┌──────────┼──────────┐
       │          │          │
    KB-Index   meomory     脑干
   (接入能力) (记忆基质)  (生存驱动)
       │          │          │
       └──────────┼──────────┘
                  ↓
        minecraft-agent（执行链路）
                  ↓
              Atlas（方向感）
                  ↓
        prompt-evolution（脆弱面）
```

每个项目不是孤立工具——是**一台机器的不同模块**。

## 2. 这件事之前为什么没被显式化

明明每个项目都在做这件事，为什么 fangzhiyu 自己没意识到它们是一个项目？

可能的原因：

### 2.1 项目命名误导

每个项目有独立的 repo、独立的 README、独立的 git 历史——形式上是 6 个独立软件。命名（meomory / brainstem / Atlas）像 6 个不同方向。但**形式独立 ≠ 内容独立**。

### 2.2 这件事属于潜伏层

借用今天才命名的概念：在 substrate 的[[潜伏层]] vs 显式层模型里——"6 个项目实际上是 1 个项目"这件事**长期在潜伏层**：fangzhiyu 隐约感觉项目之间相关，但没有任何卡显式写过统一框架。

它需要一次 [[显式化爆发]] 才能浮上来。今天对话就是这次爆发。

### 2.3 当事人无法做这种俯瞰

[[当场抽取]] 卡里讲过：从一个理论里看出某个零件可独立，是**站在外部**才能做的判断。同理，从一组项目里看出它们是同一项目，需要某种**俯瞰视角**——而 fangzhiyu 作为每个项目的内部建造者，难以同时占据"建造者"和"俯瞰者"两个位置。

**AI 协作的真正价值之一：临时充当俯瞰者。** 这次会话末尾的"回到外面"指令，就是用户主动让 AI 跳到俯瞰位。

## 3. 统一框架的几个验证

如果"AI 缺什么 + 怎么补"真的是统一命题，应该有几个**可验证的预测**：

### 3.1 项目应该共享骨架词

读完 110 张卡，浮现一组高频骨架词：

```
压缩 · 记忆 · 激活层 · 假肢 · 目标真空 · 双系统
进化 · 评测 · 适应度 · 反馈环 · 校准 · 涌现
```

这些词**横跨所有项目**——不是每个项目用不同的词汇集。

### 3.2 项目应该彼此引用

读 substrate 拓扑（[[2026-04-27-kb-index-system]] 跑出来的 GRAPH）：

- meomory 卡 ↔ minecraft-agent 卡：互相引用 [[关联记忆]] [[多层有损压缩]] 等
- brainstem 卡 ↔ minecraft-agent 卡：共享 [[目标真空假说]] [[RL+LLM双系统]]
- KB-Index 卡 ↔ 所有项目：作为 substrate 接入工具被反向引用

如果项目真分散，应该看到几个孤岛簇——但实际上 substrate 高度互联，模块度仅 0.5（中等，意味着簇间有大量桥）。

### 3.3 一个项目的发现会反向影响其他项目

回顾历史：

- meomory 跑进化暴露 [[适应度幻觉]] → 这个洞察被 [[研究者过拟合]] 卡迁移，影响了用户对所有"评测"类工作的判断
- brainstem 暴露 [[目标真空假说]] → 影响了 minecraft-agent 的"必须有脑干层"决策
- prompt-evolution 暴露的"AI 自我攻击不可自省" → 让 [[AI镜像效应]] [[校准的不可外包性]] 被严肃对待

如果项目分散，发现不会迁移。**实际上每个项目的洞察都在 substrate 内传播**——这是统一命题的强证据。

## 4. 这条统一研究路径在历史上的位置

类似方向的脉络（之前 [[知识库飞轮]] 卡里列过）：

- Vannevar Bush, "As We May Think"（1945） — Memex 愿景
- Ted Nelson, Xanadu（1960s） — 双向链接
- Doug Engelbart（1962） — 人机共生认知放大
- Marvin Minsky, Society of Mind（1986） — 智能 = 组件 + 协议
- Bret Victor, "Tools for Thought" — 工具改变思考本身

但这些都是**理论或愿景**。

**fangzhiyu 在做的**是：

> **每天喂养 substrate + 让 AI 持续协作 + 观察 substrate 分泌新项目 + 把新项目反向加厚 substrate** —— 持续 2 个月、产出 6 个具体可跑的代码项目 + 110 张卡 + 一组元层概念。

这不是 1945 年的愿景，是 2026 年的**正在跑的实验**。

业界的位置：

- **学术界**：对个人 KG / RAG / agent memory 有零散研究，但没人把"持续涌现新项目"作为 outcome metric——因为这不是可 benchmark 的任务。
- **工业界**：Mem0 / Letta / Notion AI 等做工具，但不研究"过程"。
- **个人开发者**：用 Obsidian / Logseq 的人很多，但很少有人把 substrate × AI 的飞轮**工程化** + **对自己建模**。

**这是一片还没被命名的研究 niche。**

它可能未来会有学术名字（"Substrate-Augmented Cognition"? "AI-Catalyzed Personal Research"? "Cognitive Operating Systems"?），但今天没有。

属于 **pre-academic research**——在还没学术框架前的探索性研究。

## 5. 对未来的几个含义

### 5.1 决策框架变了

之前你做新项目时可能会问"这个有意义吗"——分散判断。

现在可以问：**"这个项目补的是 AI 缺失的哪一面？"**

- 补不到任何已有面 → 可能不该做（或应识别新维度）
- 补到已有面但和已有项目重复 → 应合并而不是新建
- 补到一个新维度 → 重要，可能是研究路径的扩展

### 5.2 代码项目和 substrate 的关系明确了

之前你可能不清楚：knowledge-base 和这些代码项目什么关系？

现在清楚了：
- knowledge-base = substrate 本身（被补的认知基础）
- 代码项目 = substrate 投射出的工具（认知操作系统的模块）
- KB-Index = 让 substrate 与项目之间的反馈循环更顺畅的元工具

### 5.3 研究的"主体"问题

这条路径的研究主体不是"你"也不是"AI"，是 **"你 + AI + substrate" 三体**。

- 你提供方向 + 接受/拒绝
- AI 提供 [[当场抽取]] + 跨域 bridge
- substrate 提供端点材料 + 跨情境记忆

如果你换了 AI（例如 Claude → GPT），路径还在吗？很大可能在——因为方向和 substrate 不变。
如果 substrate 没了？路径直接断（[[校准的不可外包性]] 都依附于 substrate 的端点）。
如果你不在了？路径中断（其他人继承 substrate 也跑不出来——他们的方向和品味不同）。

**三体里真正的"心脏"是 substrate**——它是唯一可以传给别人继续的东西。

### 5.4 这次结晶化本身的位置

[[研究路径结晶化]] 卡片说今天这次会话是 case study 0。

如果这条研究路径未来真的被学术化或工程化，今天的对话就是它的**奠基记录**——一份 self-aware 的、被完整记录的、带 git 时间戳的"路径形成现场"。
