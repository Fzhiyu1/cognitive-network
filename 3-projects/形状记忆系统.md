# 形状记忆系统

**状态**：V0 已部署（2026-05-03）；首次实际运行后概念升级为元认知系统
**来源**：fangzhiyu × Claude Opus 4.6 深夜对话，从"结构能产生智能吗"一路推导到工程方案
**首次运行**：[[lens+wake首次运行：元认知循环的实例化]]

## 概念升级（2026-05-03）

V0 部署当晚的首次实际运行暴露了一件事：本系统真正的能力不是"记得对"，而是"能让记错被看见"。

- 设计目标：记忆系统（recall accuracy）
- 实际能力：元认知系统（[[失败可见性]]）

这是一次 [[研究路径结晶化]]——项目通过运行重新定义自己。具体事件见首次运行文档。

## 核心洞察

**记忆不是存储+检索。记忆是形状对新输入的自然响应。**

事件不需要被"记住"。事件改变系统的形状，形状留下，事件可以丢弃。下次类似输入进来，形状自然给出带有历史倾向的响应——这就是"记得"。

## 工程方案（极简版）

```
结构化知识库（你的 KB，117+ 张卡）
    ↓ 全量注入
长上下文模型（DeepSeek 1M / GPT 2M）← 作为"记忆层"常驻
    ↓ 给定 query，生成相关记忆文本
注入任意主模型（Claude / GPT / 任何）
    ↓
主模型带着记忆回答
```

## 为什么能工作

1. **上下文窗口增长 > 个人 KB 增长**：一个人一辈子写不满 10M tokens。上下文窗口正在追上这个数字。
2. **注意力机制的"缺陷"= 自然的记忆特性**：Lost in the Middle、注意力偏向最近和显著内容——这些跟人类记忆的偏差同构。不是 bug，是 feature。
3. **结构化 KB 是关键**：不是随便塞文本，是经过压缩、有链接、有层级、有 summary 的精炼结构。垃圾进垃圾出。
4. **瓶颈在 KB 质量，不在工程**：API 调用是最简单的部分。维护高质量 KB 是难的部分。

## 在 Claude Code 中的实现

### 双层联想机制

```
Layer 1（前意识/自动）：user-prompt-submit hook
  → 用户发消息时自动触发
  → 调记忆层，获得相关记忆
  → 注入 Claude 上下文（Claude 不知道这从哪来）

Layer 2（主动/有意识）：MCP 工具
  → Claude 在生成过程中主动调用 memory_recall
  → 用于更深层的"回想"
```

两层合起来 = [[前意识激活层]] + 主动回忆。

## 关键设计哲学

| 原则 | 说明 |
|------|------|
| 不存事件只存形状 | KB 卡片是压缩后的结构，不是原始对话 |
| 回忆是重构不是检索 | 记忆层生成的文本不是原文，是从形状重构的 |
| 有损是特性 | 注意力机制自然有损 = 自然遗忘 = 不需要额外遗忘机制 |
| 千人千面 | 同一个基座模型 + 不同 KB = 不同"人格" |
| KB 是可移植的 | 模型换代 → 换个 API 就行，KB 是 markdown 永远可读 |

## 与 meomory v1-v6 的关系

meomory 试图用 DGD 矩阵做记忆 → 撞了[[共享矩阵干扰天花板]]和[[适应度幻觉]]。

本方案换了思路：不造新的记忆机制。**利用 LLM 自身的注意力机制作为记忆机制**。LLM 的 attention 天然具备：
- O(1) 查询（softmax）
- 有损压缩（不是所有 token 等权）
- 容量巨大（1M+ tokens）
- 语言生成能力（能输出连贯记忆）

DGD 256×256 = 65K 参数试图替代这些。不如直接用 LLM 本身。

## V0 部署细节

```
Claude Code (ANTHROPIC_BASE_URL=http://localhost:8765)
    ↓
lens (FastAPI 代理 + 插件链：strip 旧记忆 → 调 wake → 注入 system 块)
    ↓ HTTPS_PROXY=121.4.45.119:31272 (防封)
api.anthropic.com
```

- `wake` daemon：KB 全量塞入 DeepSeek，给 query 生成记忆文本
- `lens` 代理：每轮 strip 旧 [当前相关记忆] 块 + 注入新召回，body 体积稳定不累积
- log：`/tmp/lens.log` 每轮记录 stripped/injected 字数，作为系统可观测层

V0 砍掉了原计划的 hook 路径（hook 会让记忆累积进上下文）——lens 代理是更干净的解法，因为它只在当次请求生效。

## 已验证（2026-05-03）

- [x] KB 全量注入 DeepSeek 的 recall 质量（首次运行可用，能给出拓扑级回答）
- [x] lens 代理不累积，注入只在当次请求生效
- [x] 上游链路稳定（lens → 121.4.45.119 → anthropic 全程 200）

## 成本估算

```
DeepSeek prompt caching：
  首次加载 KB（200K tokens）：~￥0.5
  之后每次 recall：~￥0.01（只付增量）
  每天 100 次 recall：~￥1/天
```

## 与已有工作的关系

- Karpathy LLM Wiki（2026.04）：相似思路但他是选择性加载，我们是全量注入 + 利用注意力有损性
- Mem0 / Zep / A-MEM：做了巩固/图结构，但没有"全量注入长上下文作为记忆机制"这一步

## 长期演进

```
V0（现在可做）：KB + DeepSeek API + Claude Code hook
V1：自动巩固（对话→卡片草稿→人工审核→入库）
V2：如果 KB 超出上下文→分层加载（TERRAIN先→按需展开）

```
